# 从零搭建双向量输入模型

这是一个可复制的工程纵切示例，不是前向验收记录。示例只覆盖两个批次对齐的稠密向量、两个可训练编码器、一个可训练门控拼接融合和一个标量 MSE 输出；输入是骨架生成的合成张量，不代表真实数据。

## 需要用户填写或选择

| 项目 | 本示例值 | 用户要按任务确认的内容 |
| --- | --- | --- |
| 模型模块 | 骨架默认模块 `model_starter` | 使用默认模块名，或填写自己的新模块路径；已有项目配置时停止创建并先检查 |
| 输入名和每样本形状 | `left=4`、`right=6` | 两个输入各自的稳定名称、维度顺序及是否需要动态轴；形状不含批次轴 |
| 输入 dtype | 省略，运行时使用所选 PyTorch 的默认浮点类型 | 实际数据类型；若两路 dtype 不同，需决定在哪里显式转换 |
| 输出和损失 | `score=1:mse` | 输出名称、特征数、损失以及真实目标的形状和语义 |
| 组件工厂 | `dual_input_components:vector_encoder` 两次；融合先用 `gated_concat`，可换成 `plain_concat` | 项目模块目录、自己的工厂入口及模型构造参数 |
| 组件参数 | 编码器宽度 `4` 和 `6`；融合输入数 `2` | 编码器输出宽度、融合输入数，以及融合输出是否满足预测头输入 |
| 输入批次 | 骨架自动生成的 batch size 为 `2` 的合成数据 | 用户数据适配器、批次大小、目标及样本语义 |
| 执行环境 | 用户选择的 Python 和其中可导入的 PyTorch | 解释器、PyTorch 构建、设备、额外依赖和项目模块搜索目录；工具不替用户安装或绑定 |

## 操作路径

1. 在一个新建空目录打开开发中的 Neovim 工作区。按 `n` 创建模型，填写模块名（默认 `model_starter`）、两个输入 `left=4`、`right=6`，输出 `score=1:mse`。预览计划并确认创建；从回执页按 `e` 打开生成模型源码。骨架创建回执上的 `p` 可选运行默认恒等编码器 smoke check；它不是本示例自定义原型的首次前向。
2. 将本目录的 `dual_input_components.py` 复制到项目根目录，作为 `dual_input_components.py` 保存。检查并选择本次使用的 Python 环境；确认其中有兼容的 PyTorch。工厂导入和前向会执行项目 Python 代码。
3. 返回工作区面板（可执行 `:ModelMaven`）按 `A` 打开装配入口，选择同时修改多项，填写并预览以下组件绑定。预览会实际导入工厂并执行候选前向；记录该报告和输入/环境上下文。

   ```json
   {"sets":{"left_encoder":"dual_input_components:vector_encoder","right_encoder":"dual_input_components:vector_encoder","fusion":"dual_input_components:gated_concat"},"params":{"left_encoder.width":4,"right_encoder.width":6,"fusion.inputs":2}}
   ```

4. 在装配预览报告选择“用新输入重验并保存”或“要求相同输入”（仅当报告提供该选项时可用），然后显式确认保存配置。若报告没有可核对输入摘要，不能声称前后使用了相同输入。
5. 装配候选的前向是本例自定义模型的首次真实前向；只有候选报告成功且配置写入确认成功，才能分别记录这两个事实。
6. 配置写入成功后，回到工作区面板（必要时执行 `:ModelMaven`）按 `p`，对已保存装配的模型作一次独立前向。检查实际输出形状、模块调用及报告；只有这次成功，才记录保存配置后的重验通过。创建或仅通过预览都不能替代该独立观察。
7. 为明确展示组件替换，回到工作区面板按 `A`，只把 `fusion` 工厂改为 `dual_input_components:plain_concat`，参数保持 `fusion.inputs=2`。重新预览候选，选择输入处理方式并确认写入，再回工作区按 `p` 独立运行替换后的模型。两种融合都输出 10 个特征，预测头接口不变；权重状态或完整环境并未因此固定。
8. 从工作区按 `z` 回到同一个模型源码 buffer 修改模型源码，或打开组件 buffer 修改组件，使用 `:write` 保存后再次前向；运行使用项目中已保存的代码。组件配置装配和源码编辑是不同操作；项目已存在时不要重新创建骨架。需要检查具体调用路径时以观察报告为准。
9. 把合成输入替换为真实数据前，用户需实现或选择兼容的 batch 工厂，并明确输入绑定与目标。确认项目信息、源码 buffer、解释器及必要模块目录后，再前向验证。

骨架操作及快捷键取决于实际工作区版本。若菜单或 CLI 不支持所需字段，记录实际版本和能力报告，避免手工假设计划已提交。

## 代码与接缝

- `dual_input_components.py`：用户拥有的编码器与融合工厂。编码器输入分别是 `[batch, 4]` 和 `[batch, 6]`，此示例保持输出宽度；融合接收按骨架编码器顺序排列的张量列表，返回供骨架预测头使用的 `[batch, 10]` 张量。
- `gated_concat` 到 `plain_concat`：同一 fusion 槽位的可替换工厂。前者带有可训练逐输入尺度，后者直接拼接；二者保持相同输入数和输出宽度，方便检查候选预览与提交后的再次前向。
- 骨架模型源码：持有两路编码器、融合层和输出头。若改变编码器返回值、dtype、融合宽度、模型签名或输出结构，必须同步调整融合、预测头或模型源码，并重新前向。
- 项目配置：记录工厂入口与注入参数，不包含组件实现代码。复制组件文件到目标项目后，用户仍需审阅源码和 Python 搜索路径。
- 输入工厂/适配器：本示例未提供真实数据读取、预处理、标签或数据完整性检查。应由用户针对数据和隐私约束实现。

## 明确的边界与待补缺口

- 合成批次只能说明代表性的双稠密向量接缝；它不验证真实数据、其他 shape/dtype、动态结构、分布式执行、任意 Python 网络或其他框架。
- 骨架会把非原生编码器输出按声明的动态轴归约并展平；这不等价于任意自定义张量树或嵌套输出接线。复杂结构需由用户改写源码并为融合/输出头实现相应契约。
- 组件配置预览验证所选工厂和候选前向的范围受实际 CLI 能力与报告约束；导入可成功不等于用户任务语义正确，也不证明未观察分支。
- 从零双输入的完整人工路径、同一 buffer 返回/焦点、源码修改后的持久性与重验，尚需在实现冻结后由 P4 统一走查。本目录不包含运行报告、性能数据或用户研究结果。
