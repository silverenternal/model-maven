# 统一模型工作区：主线和实现对照

本文根据当前源码与本地走查整理；静态分镜是目标示意，真实操作及其限制见 [本地走查记录](acceptance/local-workspace-walkthrough.md)，不能代替真实用户验收。命令启动器和 `:ModelMaven` 进入同一 Lua 工作区，源码仍由当前 Neovim 的普通 buffer 编辑。[已有项目接入](existing-project-adaptation.md)说明具体接缝。

## 主线和用户决定

| 场景 | 默认呈现及主要动作 | 用户需要决定 | 后端处理与可返回的位置 |
| --- | --- | --- | --- |
| 空目录或未配置项目 | 创建、接入、查找；`c` 可从打开或最近文件发现已配置项目 | 选择起点、名称与路径；创建计划预览后才写入 | 读取项目配置与静态候选；取消不创建文件，返回同一源码窗口和面板 |
| 已有模型，缺输入 | 选择代表输入，或先检查模型 | 用现有输入工厂、自己写适配器，还是保留未配置状态 | 区分工厂声明和真实输入；选择本身不代表运行通过 |
| 准备前向 | 显示项目、模型、输入、Python、路径及执行后果 | 确认后执行，或返回源码修改 | 执行独立 Python worker，报告实际观察与诊断；不是所有分支的证明 |
| 前向失败 | 首先查看诊断，可进入相关模块或可信源码位置 | 是否定位、手工编辑、换输入或再次运行 | 显示实际错误与有界调用栈；无法验证的源码位置保持未知，原始报告可展开 |
| Layer 候选 | 当前目标、源码差异、权重/共享影响与候选前向 | 取消或确认条件提交；提交后另行独立重验 | 按配置、源码、候选和输入身份核对；验证失败按事务机制回滚，仍可能已有用户代码副作用 |
| 手动监督 | 已观察模块的输入或输出端口、用户命名的语义、规则和违规后果 | 用户指定语义和规则，决定是否在支持的训练中启用 | 不自动推断标签；预览仅说明已观察输入与调用范围。当前输入规则在模块调用后读取参数，原地修改可能改变观察值，不能阻止该调用或其副作用 |
| 试跑或正式训练 | 模式、入口、参数、设备、监督和执行/写入后果 | 选择受管步骤、手动步骤或用户循环；确认启动 | 管理运行和检查点；后台启动回执未知时通过 `H` 查证，不自动重复 |

这些阶段可以跳转，不是必须依次完成的向导。`U` 可填写当前目标，保存在这个工作区会话内，清空即可移除；目标本身不驱动或执行任何操作。`x` 展开动作，`f` 搜索，`r` 看报告，`o`/`z` 回到源码，`?` 查帮助。计划和报告使用临时面板；源码只有原生 buffer，未保存内容不会由工具自动保存。项目候选读取的是当前会话的文件列表与 Neovim 历史记录，可能缺失实际最近项目；它不是产品自己的完整最近项目历史。

从观察到的模块或张量连接发起源码修改时，如果候选未通过预览，可查看失败报告；若该位置有无歧义的项目源码身份，也可选择打开记录的实现或构造位置。打开时重新核对文件身份；记录的位置未必是失败原因，任意 Python 控制流仍需自行修改。该路径尚待实际操作验收。

已配置的旧图像分类项目可从分类声明菜单打开图画布，开始独立的新图草稿。没有既有图或图草稿时，也可选择以 `classification:model` 为单个不透明块建立输入、输出、交叉熵及 `classification:batch` 草稿；工厂签名、实际输入和损失须在运行时验证，块内部仍由原源码控制。连接分类目录图像时会建议旧声明的数据目录，用户仍需核对数据、映射和预处理。现有源码、训练设置、权重和监督规则不会自动迁移到图中；生成或切换模型及应用数据仍需分别审核。该入口不是旧项目自动转换，尚待实际操作验收。

`A` 的装配菜单可以直接选择已保存的组件绑定并预览移除，也可以逐项组合组件替换、输入接线和编码器输出；草稿可在可滚动窗口查看并撤销单项修改，设置工厂时可用 `?` 搜索已注册且声明支持构造的 Layer 组件，预览未通过或取消时在项目上下文未变的情况下返回草稿。草稿仅保留在当前工作区会话内，不写入磁盘；上下文变化后须审核并明确选择用于新配置，再重新预览；切换到其他项目时不会自动覆盖旧草稿，当前配置不可用时仍可查看或丢弃。使用面板 `q` 关闭时，有改动的草稿需要明确丢弃；其他关闭方式尽力提示草稿未保存，异常退出不提供自动恢复。模型内部已有的普通层仍从 Layer 菜单或原生源码 buffer 修改。保存前仍需代表输入、预览和单独确认；本地骨架已走查从模型发现接缝、选择用户工厂、接线、预览、保存与独立前向，其他配置仍需核对。

执行确认区分项目参数名称和会话覆盖名称，参数值需在项目设置或会话参数中查看；模型参数沿用项目值并叠加会话覆盖，显式切换输入工厂时不沿用项目输入参数。对支持的新版 CLI，普通操作未明确选择解释器时会先不启动 Python 地读取其选择提示，向用户显示候选并固定到本次操作；历史运行和环境操作仍按各自的选择规则处理。提示不能证明解释器文件或环境在运行前后没有变化，旧 CLI 或无法确定时仍明确显示未知，用户可按 `e` 选择。此交互尚待最终人工体验确认。

修改后的独立前向只有在执行成功、上下文和已知解释器选择一致，且输入内容摘要与预览相同时，才清除等待重验状态。解释器选择或输入不同、无法核对时仍展示该次前向结果，但继续保留重验入口；同一路径不证明解释器内容、权重或完整环境一致。该规则尚待人工体验验证。

输入摘要预览在工作区报告直接显示最多三项有界的嵌套字段、形状和 dtype，更多内容在 HTML 中；结构部分不展示数据值，但字段名称可能敏感。已有样本标签、ID 和字段名称仍可能写入预览文件，应按实际数据敏感度处理。深层或过多字段会标明省略，该描述尚待最终人工体验。

每次请求数据预览都会重新调用所选数据工厂，而非仅凭用户声明的数据指纹、源码和环境锁复用旧预览；工厂、变换或 renderer 仍可能有未记录的随机性或状态。批次工厂的样本位置不被当作稳定样本 ID，数据指纹保留为用户声明的数据版本。这会增加重复预览的运行成本；旧报告仍可查看，内容绑定的安全复用留待实现。该行为尚待最终人工体验。

普通批次工厂的输出按一个整体预览，避免猜测首维是否为批次轴；工厂若返回受采样适配器处理的数据集，则依据采样记录拆分。用户可选择 `single-raw`，明确把可迭代的工厂结果整体传入并跳过数据集采样；工作区预览随该选择按整体处理。预览范围记录这些解释，不代表已验证模型的实际输入绑定；该路径尚待人工体验。

选择的模块目录在准备运行和创建源码快照时仍须存在并通过项目边界检查；快照创建后，worker 从快照核对和解析这些目录，不再要求实时目录在导入时仍存在。其他运行依赖、源码一致性及恢复条件仍各自检查，此行为尚待人工验收。

试跑、训练和可用的历史运行报告会展示监督规则的实际观察步数、检查元素数、违反数、惩罚均值和样本定位状态；未观察到的规则不等于通过。样本 ID 是用户声明，实际数据集覆盖率未知。该展示尚待最终人工体验。

受管步骤被 require 规则拒绝时，错误回执携带所选端口、规则、违反数量和已完成步数；工作区只在明确记录的受管步骤证据存在时说明工具尚未开始本步反向与优化器更新。用户代码本身的更新或其他副作用不在该保证内，也不会自动回滚；手动循环的更新状态不能据此推断。

同一训练步骤会记住监督 hook 的首次失败；即使用户模型捕获该异常，工具管理的反向、优化器更新或步骤完成边界也会再次报告失败。用户自行绕过这些接口执行的更新不受此保护；该实现尚未运行验证。

完整用户循环即使捕获监督异常，也不能通过重新进入监督上下文清除失败；若直接返回，运行会报告失败并保留已完成步数。先前已写入的 checkpoint 和用户代码副作用不会因此回滚。

受监督的完整循环只在已登记优化器返回并通过工具的更新后参数检查时计入一次更新；一次成功计数不证明用户代码中的其他优化器尝试也成功，失败的优化器仍可能已经产生副作用。

监督拒绝报告可按 `d` 在当前模型中重新检查记录的模块路径，支持步骤失败中的嵌套原因以及完整循环直接返回的规则错误；该检查会重新确认并执行当前项目代码，历史运行的模型不一定与当前模型一致，路径也可能已不存在。报告上下文改变时必须重新打开记录或从当前模型检查。

## 核心价值与工具边界

优先验证的任务是：工程师接入自己的多输入或带共享层的 PyTorch 模型，选一批真实或有代表性的输入，在当前源码窗口定位一次前向问题，修改后用相同上下文重新观察。随后再验证从空目录创建多输入骨架、替换用户组件和接入真实数据。实际顺序可由用户跳转；这里的先后是产品验证优先级，不是界面强制流程。

| 范围 | 当前提供的接缝 | 用户代码或外部工具负责 | 尚不能据此声称 |
| --- | --- | --- | --- |
| 核心：理解、修改、重验 | 代表输入的真实前向、模块与张量连接证据、可定位源码、受支持的 Layer 预览和条件提交 | 提供模型工厂及输入；动态或不支持自动编辑的部分在原 buffer 手工修改 | 单次观察覆盖所有动态分支；任意 Python 网络均可自动重写 |
| 支撑：从零创建和输入环境 | 可编辑多输入骨架、用户组件接缝、合成批次或已有输入工厂、解释器与项目模块目录选择 | 实现实际网络、数据解析和任务目标；决定依赖与设备 | 骨架示例损失适合真实任务；环境选择等于依赖与数据已经复现 |
| 支撑：手动监督 | 用户标记已观察端口，定义规则并在代表批次预览；支持的训练模式可选择启用 | 指定语义、限制和违规后果；自定义循环实现约定的监督协议 | 自动理解模型语义，或预览通过代表所有样本和路径通过 |
| 衔接：训练、评估和导出 | 受管步骤、用户手动步骤或完整循环接缝；运行记录、checkpoint、用户评估器及导出 | 非受管更新、数据迭代、外部实验工具与其生命周期；为受支持恢复提供状态 | 任意训练框架、分布式拓扑或外部实验服务已被内置支持；任意恢复都严格复现 |

待检验假设：与工程师惯用的 PyTorch 和 Neovim 流程相比，统一的观察、源码定位和条件预览能减少一次复杂修改中查找问题及核对影响所需的时间和求助。应分别记录准备适配代码、首次前向、定位、修改和重验的时间、失败及人工帮助；不要把工具下载、依赖安装或输入构造成本从对比中省略。尚无对应无引导用户证据时，这只是待验证假设，不能作为商业收益结论。产品负责定义任务与反馈；后端负责事实和限制；工作区负责呈现决策与返回路径；实际比较需由目标工程师完成。

能力逐项决策如下；“复用”仅表示使用已有实现，不等同所有变体均已验收：

| 能力 | 首期复用 | 用户已有代码或工具的接入 | 继续完成和验证 |
| --- | --- | --- | --- |
| 创建 | 可编辑骨架和用户选择的输入输出 | 用户直接编辑源码、实现或注入组件 | 验证更复杂项目和真实数据；不把骨架当完整模型 |
| 监督 | 手动端口语义、规则预览及支持路径中的可选规则 | 用户定义规则与后果；自有循环按其契约决定如何使用 | 进一步验证规则、覆盖与循环接缝；不设置规则时无需先配置监督 |
| 训练 | 受管步骤、手动步骤和用户完整循环入口 | 保留用户数据迭代、优化器、训练循环和外部实验工具 | 明确各入口的状态、停止和恢复能力；不宣称通用框架或分布式支持 |
| 评估 | 运行记录与用户评估器入口 | 用户提供评估函数、数据及指标，也可沿用外部评估工具 | 验证更多评估器、模型与运行环境；不推断指标的因果关系 |
| 导出 | 已支持的变体代码与产物导出 | 用户继续维护生成的代码并选择自己的打包或部署工具 | 按实际变体、依赖和目标环境确认可重建性，不承诺通用部署格式 |

本地独立模型已分别走查不启用监督的试跑、用户循环和用户评估器；具体输入、结果与限制见 [统一工作区本地走查](acceptance/local-workspace-walkthrough.md)。这是工程观察，真实工程师任务、无引导比较和商业价值仍待后续验收。

## 40/80 列静态分镜与焦点

下面是按当前 Lua 工作区实现整理的静态分镜，不是屏幕截图；实际 40/80/120 列布局和部分操作已有本地走查，完整七屏逐键体验仍待核对。阈值按打开工作区时的**当前源码窗口**宽度判断：小于 60 列且普通 buffer 可安全隐藏时，在同一窗口切换源码和面板；否则保留源码窗口并新开面板。可用宽度 40 列因此采用单窗口切换；80 列采用底部面板分屏（高度约为源码窗口高度的 40%，限 3–12 行）；只有宽度达到 100 列才采用 36 列侧栏。高度不足、用户布局和自动命令可能改变实际结果，仍需实机核对。

```text
40 列 · 同一窗口切换；面板按 z 返回源码
+--------------------------------------+
|SOURCE: model.py [+]                  |
|def forward(self, x):                 |
|    return self.layer(x)              |
|                                      |
|focus: source buffer                  |
+--------------------------------------+
+--------------------------------------+
|WORKSPACE                             |
|Goal: unset [U]                       |
|Next: choose input                    |
|[b] input [i] inspect                 |
|[p] forward [x] actions               |
|[r] report [?] help                   |
+--------------------------------------+

80 列 · 源码窗口保留，工作区在底部；焦点按窗口导航切换
+------------------------------------------------------------------------------+
|SOURCE: model.py [+]                         PROJECT: ./demo                  |
|def forward(self, x):                                                         |
|    return self.layer(x)                                                      |

+------------------------------------------------------------------------------+
+------------------------------------------------------------------------------+

+------------------------------------------------------------------------------+
```

框线和内容行分别按 40/80 个 ASCII 终端单元排版；ASCII 文案是便于核对占宽的静态骨架，不是产品逐字截图。40 列原生普通 buffer 可在源码与面板间同窗切换；图中按 `z` 表示返回源码，实际面板也可用映射帮助确认按键。80 列保留源码窗口并在底部开面板；创建后核对新窗口仍显示原 buffer 才替换成面板，失败时提示且不覆盖已有窗口。面板与源码用 Neovim 窗口导航；`:ModelMaven` 返回当前项目。动作搜索、报告、模块详情等仍可能另开临时分屏。键位随动作状态变化，`?` 查看映射，`x` 展开动作，`f` 搜索动作；普通源码输入由原 buffer 接收。在 Linux、Neovim 0.12.6 的实际走查中，40 列为同窗切换、80 列为上下分屏、120 列为左右分屏；40 列已操作源码切换、保存和返回，80 列已操作中文输入与保存。详细结果见 [本地工作区走查](acceptance/local-workspace-walkthrough.md)。具体用户布局、自动命令和其他终端仍可能改变结果。

### 宽屏、编辑器配置与实际边界

120 列及足够高的独立源码窗口实测为源码居左、工作区面板居右；按 `Ctrl-w` 与方向键切换窗口，源码直接由 Neovim 输入与 `:write` 保存。诊断、模型详情和报告按需打开临时原生窗口，`q` 关闭当前报告或面板。新手可在面板通过 `?` 找到输入、保存、窗口切换与独立会话退出说明。状态以 Neovim 的 buffer 和窗口为准，不另造文本编辑器；旧图形连接演示不代表 Python 源码编辑能力。

独立启动器、普通 Neovim 及隔离 LazyVim 均使用同一 Lua 工作区。普通会话的双分屏和未保存 buffer、隔离 LazyVim 的现有窗口、主题、键位和 Ruff LSP 已做本地检查；未覆盖所有个人插件、版本与系统。高度不足、特殊 buffer 或自动命令改变窗口时，布局可能回退或中止并提示，不据此承诺所有组合均能自动恢复。按本项完成的是代码中心布局设计及所述本地行为；真实项目完整任务和其他配置仍由后续工作单独验收。

## 七屏接力：设计问题与当前入口映射

`todo.json` 的 `interaction_spec.screens` 是七个用户问题的设计分类；当前产品实际是一个代码中心工作区加按需对话框、报告和临时分屏，并没有七个固定页面。以下“显示”是静态文案原型；按键与失败去向按当前源码映射。打开、创建、前向等具体动作仍需逐键实机走查。

| 入口条件 | 当前可见事实与首个决定 | 路径和失败返回 |
| --- | --- | --- |
| 空目录/未配置 | 工作区标为未配置，源码仍是当前 Neovim buffer；用户决定创建、接入、继续自有循环或切换项目 | `[n]` 创建、`[a]` 接入；创建计划确认前不落文件。CLI 无法启动时由工作区报告错误，并可从 `[E]` 选择环境/CLI 或退出。 |

跨屏不变量：执行用户代码、写文件、安装/下载、启动训练均须在动作前呈现范围并单独确认；预览不是提交授权，成功回执与独立重验是不同事实。当前工作区动作通常以 `vim.ui` 选择/输入、报告或临时 buffer 承载；Esc/取消回到调用它的面板回调，错误后能否保留完整表单需按具体流程核对。原生源码 buffer 不由工作区自动保存。进程关闭、异常退出和项目切换下的恢复不作保证。当前按键只是现有源码路径的索引，不等同于已走查逐键序列，也不声称各状态都显示同一快捷键。

P4 人工走查每个关键状态都需现场记录四项；源码静态审阅只能给出“当前代码依据”和需验证的问题，不能替代用户结论：

| 状态 | 当前建议及源码依据 | 用户确认/决定 | 下一步与现场待核 |
| --- | --- | --- | --- |
| 创建 | 未配置时提供创建/接入入口；推荐创建的依据是用户选择从零开始，而非自动判断项目适合模板 | 项目位置、模型起点、模板默认与最终写入计划 | 计划确认后进入源码；观察取消/冲突后计划和选择是否仍可改、返回位置是否稳定 |
| 前向失败 | 建议查看报告/源码，因为诊断和已观察位置是实际证据；位置不可信时应显示未知 | 是否换输入、编辑、重试；重试仍须确认将执行的代码 | 回原面板或源码；记录错误、输入选择和报告是否保留，不能把“可重试”说成根因已知 |
| 修改预览 | 推荐先预览，以便看候选差异、共享/权重影响和验证范围 | 取消或提交；提交与之后的独立重验分别决定 | 取消回原模型/代码；提交回待重验状态。记录失败是否保留草稿、并发冲突时用户看到什么 |
| 前向成功 | 显示本次输入、源码/环境上下文及实际观测；可建议查看模块或继续修改，理由是当前报告可用于定位和决策 | 继续查看、改源码、标监督或另行试跑 | 返回同一工作区；核对报告新旧、过期提示、焦点和源码未保存状态 |
| 运行状态未知 | 建议先查 `[H]`/运行记录，因为启动回执不足以证明任务状态 | 查询 request ID 后由用户决定恢复、等待或新建；不得自动重启 | 结果仍未知时保留未知和请求身份；现场确认查询结果与本地待确认标记如何呈现 |

首次打开和恢复隐藏面板时，分屏创建后会核对新增窗口及其原 buffer；如果自动命令改变了窗口布局或放入其他 buffer，停止放置面板并保留窗口。无法安全判断时可能留下额外分屏，用户可自行整理；这些冲突处理尚未在实际插件配置中走查。

工作区 `[Z]` 可浏览已保存变体，并在详情中选择对固定修订执行一次前向；使用当前输入和运行时选择，执行前要求支持条件变体观察的 CLI 并重新核对变体基准。结果标为独立观察，不替换当前源码模型的上次前向或用于其源码编辑；可按 `[v]` 只读浏览本次报告中的模块，对具有无歧义项目源码身份的观察可核对摘要后打开实现。打开的原生文件仍可编辑，修改源码不会直接修改变体配方，且可能使变体的源码清单过期。详情还提供 Layer 编辑预览；详情现可选择固定修订的受管、手动或 PyTorch 用户循环进行试跑及后台训练；持续切换尚未融合到此入口。用户循环负责取数和更新；本机真实模型已完成后台用户循环及 checkpoint 续跑，其他循环和设备仍需各自核验。已在本地复杂模型副本中通过工作区选择 `working` 变体并完成真实前向，报告标明独立观察；另在同一类本地样例中通过类型发现完成变体 Layer 编辑预览并取消；另在当前项目的新变体中保存一次 Layer 替换并独立重载前向；其他变体场景仍需逐项核对。

新建骨架时，输入名和具名输出各自在 NFKC 规范化后检查碰撞；名称本身按用户输入保留，不静默改写。接线仍要求精确使用声明的名称；若输入只是规范化形式相同，CLI 提示正确的原始名称。统一工作区在包含 Unicode 名称时要求 CLI 声明该检查能力。历史骨架不会自动迁移；相关行为尚未人工验证。

运行期间对已打开的项目文件比较 buffer 修订以及文件类型、设备、inode、大小、修改时间和状态变化时间；观察到变化时，结果标记为上下文已变化。这是变化提示而非内容快照，未打开的文件、外部依赖和文件系统未反映的变化仍可能未被发现；该处理尚待人工验证。

在空白源码区接入已有项目时，若静态路径只找到一个模型源码候选，窄窗口会先把它加载到原生 buffer 并保留任务面板；按 `z` 可查看，候选仍标为未经运行验证。加载会触发用户已有的 Neovim 文件读取自动命令。

首次打开额外的项目源码 buffer 本身不再使最近结果自动过期；已有 buffer 的重新读取、编辑、保存和文件变化仍会使其过期。执行和提交前仍检查打开的 buffer 与磁盘，未打开的外部文件变化不能由这一规则完整捕获。该行为尚待人工体验。

独立启动时，在加载工作区模块前检查 Neovim 0.10 版本；版本不足会提示升级或通过 `MODEL_MAVEN_NVIM` 选择其他可执行文件。已有会话插件也有版本检查；真实旧版 Neovim 的启动表现尚待人工核对。

- 用户填写的目标只保留在工作区会话中，尚不跨会话恢复或与所有报告关联；建议动作仍主要依据项目状态和最近结果，不推断目标是否完成。
- 错误到可定位对象的转换受实际来源证据限制；动态加载、外部库、未观察分支与磁盘竞态不能伪定位。
- 原生会话、隔离 LazyVim、独立启动器及部分窄屏行为已有本地走查；个人插件组合、其他平台、真实用户价值和性能仍未充分验证。
- 有些高级动作需要工厂、参数或路径；这些信息可以展开或由用户输入，但不应作为理解首个下一步的前提。
