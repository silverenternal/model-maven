# Generated one-batch evaluator

A model generated by a CLI advertising `project.scaffold_one_batch_evaluator_v1` includes `module:evaluate`. Scaffold preview and receipt identify it as `starter_evaluator`. Existing generated files are not changed automatically.

The evaluator accepts the evaluation worker's `(model, data, context)` contract. Its data factory must return a single batch envelope with nonempty named batched tensor inputs and the targets required by the generated step. It applies `context.transform_batch`, moves tensor leaves when `context.device` was explicitly chosen, calls the generated `step`, returns its weighted loss as `loss`, and reports the actual batch size. The worker applies inference mode and validates the reported metric. An explicit sample limit smaller than the batch causes an error; the evaluator does not silently truncate data.

This measures one batch only. It does not compute dataset-wide metrics, prediction samples, coverage, stratification, or a verified data fingerprint. The evaluator and data factory are project code; users can replace them for their task. Selecting an evaluation split name does not automatically pass that split to the data factory: configure its data parameters separately. CSV split parameters require a compatible generated or custom adapter.

Generated MSE steps require prediction and target to be tensors with exactly equal shapes; they reject broadcasting with an error naming the output and both shapes. This applies to training and this evaluator. Projects needing intentional broadcasting can supply a custom loss. Existing generated source is not rewritten automatically.
