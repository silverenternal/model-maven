# 产品验收证据台账

`requirements.json` 保留旧产品规格的要求、责任任务与证据索引。旧文件名和来源路径用于追溯记录时的规划版本。两仓库当前的开发任务和交付验收见[总计划](../../todo.json)。

## 判定原则

- `missing` 表示当前没有足以证明整条要求的证据；它不等于断言代码完全不存在。
- `implemented` 只表示有实现，不能代替整条端到端验证。模块 TODO 为 done、单元测试通过或文档列出能力，都不会自动让要求变为 `verified`。
- `external_evidence_required` 用于真实用户、硬件、干净发行环境等不能靠仓库内模拟代替的验收。
- 证据记录必须绑定产品版本、代码 revision、环境、精确命令、退出码、覆盖范围和未覆盖范围，格式见 `evidence.schema.json`。模拟/跳过/未运行应如实记录。
- D0 与 D1 分开判定；D2 是后续候选。不能因当前易于通过而删去复杂模型、Layer 编辑或独立扩展要求。

## 并行开发边界

按[总计划](../../todo.json)的 `coordination` 分派当前工作。索引中的 `responsible_tasks` 保留旧任务到证据的对应关系。

## 历史证据基线

旧要求索引对应规格 0.13.63。QA-02 验收工具仍用该版本标记迁移前定义的场景。每批结果以各自文件记录的源码 revision 和覆盖范围为准。两仓库新建与接入旅程的验收责任见总计划的 `SHIP-01`。
