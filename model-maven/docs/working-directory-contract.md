# 模型运行工作目录接入契约（实现中）

worker 不再强制修改 PyTorch 的 CPU 线程数；线程行为由所选 Python 环境、PyTorch 设置及用户代码决定。用户可在启动工作区前设置相关环境变量，或在自己的入口中显式配置；同一项目在不同机器或环境下的线程数和性能可能不同。

只读的装配查看和装配代码生成使用所选解释器、工作目录及模块搜索目录验证原装配；生成时在独立 worker 中按同一运行时重建生成代码，并在写入前再次解析路径。工具比较请求的路径声明，并检查已观察源码和项目配置；路径声明相同不证明外部依赖或数据内容相同。已人工走查 `src` 模块目录与项目外工作目录的组合，详见 `docs/acceptance/local-workspace-walkthrough.md`；其他路径和环境仍需验证。

单项 `assembly route`、`assembly encoder-output` 和组件 `add`、`set`、`remove` 也支持所选运行时路径；自定义路径下提交时需带预览所得的源码与路径联合摘要，避免切换路径后沿用旧预览。前两者使用 `--if-source-revision`，组件增删改使用全局 `--if-source-manifest`。旧的默认路径摘要保持兼容。已人工走查使用自定义路径的组件新增，其他操作仍待走查。

显式指定新的批次工厂时，不继承项目默认工厂的参数或绑定方式；可同时显式指定适合新工厂的绑定。使用项目默认工厂时仍继承其配置。该行为覆盖模型运行、变体编辑与装配验证，尚待实际走查。

工作区项目根目录负责定位配置、源码和 Model-Maven 运行记录；用户 Python 的进程工作目录决定用户代码的相对路径解析。两者必须分别展示。默认行为保持从项目根目录启动，不新建目录、不安装任何依赖。工作目录允许选择已有绝对目录；选择后应展示其规范路径和对用户相对路径的影响。

当前 worker 对模型检查、前向、验证、Layer 编辑、试跑、训练和评估请求接受内部 `runtime.working_directory`，先完成训练源码快照，再校验并切换进程目录；它不改变 CLI 的项目根目录。Rust 请求层已有私有工作区传输字段 `MODEL_MAVEN_WORKSPACE_WORKING_DIRECTORY`：校验已有绝对目录，将规范路径写入运行请求，并在相关不支持的操作上拒绝。源码候选计划将目录加入身份，提交后验证复用该请求；历史试跑、训练和评估继承记录中的目录，选择与历史不同的目录时拒绝继续。输入无效或目录不可访问时返回结构化错误。前向和训练报告记录若干工作目录观察点；用户代码仍可能在观察点之间改变目录。工作区 `K` 已提供会话选择，完整跨操作能力仍在实现。

携带目录的 worker 请求必须声明 `runtime.user_working_directory`；不认识该能力的旧 worker 应拒绝执行。worker 重新解析规范路径，若目录路径在 Rust 检查后指向其他位置则拒绝运行；这不是针对文件系统并发变化的完整事务保证。

后续接入必须共同完成：

- CLI 在启动前规范化选择，并对不支持的操作明确拒绝，不能静默忽略；旧调用默认保持原行为。
- 请求、预览、候选验证和条件提交使用相同目录身份；选择改变后旧观察与候选失效。缓存身份必须涵盖目录，不能将匹配目录等同于完整可复现。
- 新训练记录保存实际选择；后台启动、评估、续训和重复明确继承或让用户审核变更，不能悄悄回退到项目根目录。恢复前重新检查目录是否仍可用；需进一步审查跨入口的记录完整性和报错呈现。
- CLI 的内部受管理路径和 Python 的项目元数据、快照、检查点、停止信号均使用绝对路径，核对预览、组件、数据及自定义训练各分支。不能将用户代码更改 `cwd` 当作隔离或安全边界。
- 工作区提供本会话选择、当前值和重置入口；运行确认和报告展示选择及观察范围。异步操作捕获并校验目录身份，避免旧操作写入新的上下文。
- 全部实现后再按项目要求人工走查不同布局、相对数据路径、后台训练、预览提交、续训、目录消失以及用户代码自行改变目录的情况；未走查的范围不能标记为通过。

## 项目模块搜索目录（实现中）

内部 `runtime.project_import_roots` 可指定有序的项目内相对目录，例如由用户选择 `src`。worker 在导入用户入口前按顺序添加；源码快照运行映射到快照内同一相对目录，缺失或越界会报错，不自动把该目录替换成项目实时目录。源码编辑计划、前向缓存身份和历史训练请求记录这个选择；旧 worker 必须通过能力协商拒绝未知字段。

显式选择的模块目录及其普通子目录会参与训练源码快照，即便目录名碰巧属于默认排除项；空的已选目录也会保留。训练源码快照和前向证据扫描不再仅凭 `env`、`venv`、`target`、`build` 或 `dist` 名称排除源码；它们识别当前解释器环境、`pyvenv.cfg` 和 Cargo 产物标记，显式模块目录可覆盖普通排除；选择环境或依赖目录内的某个子目录时，入口发现、训练快照和证据扫描只沿所选路径进入，不因此扫描同一边界内的其他目录；入口发现只能识别运行时环境变量或目录标记暴露的环境。扫描失败时训练快照会报错，证据缓存会停用；前向仍可执行。较大的目录可能增加扫描、复制时间和空间，Python 文件之外的资源仍不包含在快照中。版本控制目录、Python 缓存、运行记录目录和符号链接不进入快照；直接选择这些保留路径用于快照运行会报错，不能当作完整隔离。

没有项目 Python 文件时允许创建空源码快照，以便运行环境中已安装的用户库；空快照不包含库、数据或权重，不能据此认定运行可复现。独立训练导出在运行快照可核对且源码变化检查明确完成时接受空观察清单，并注明外部代码需自行准备；依赖清单和环境快照不能保证捕获全部动态导入。来源检查按解释器实际环境路径及显式模块目录区分，不仅凭目录名 `env`、`venv` 或 `target` 排除项目代码；自定义加载器等未观察的导入仍不在保证范围内。此导出路径尚未人工验证。

新导出记录训练时声明的项目模块搜索目录，在恢复时映射到导出包 `source/` 内；原训练使用自定义工作目录时，恢复者需将 `MODEL_MAVEN_EXPORT_WORKING_DIRECTORY` 设置为本机已有绝对目录。原训练使用默认项目目录时，恢复脚本使用导出包的 `source/`；旧记录缺少目录声明时沿用调用方的当前目录并提示。导出不复制数据及其他非 Python 资源，目录映射不能保证数据或依赖相同。

若运行记录包含源码快照，导出核对并复制其中在运行前后观察到的源码；这些文件之后在工作区被修改或删除，不要求恢复实时版本。快照缺失、越界或与已观察指纹不符时拒绝回退；旧记录没有快照时仍核对当前源码。部分已登记组件清单仍需核对当前文件，导出只覆盖已观察源码，未执行的动态分支、第三方库和数据可能缺失。

Rust 请求层提供私有 `MODEL_MAVEN_WORKSPACE_IMPORT_ROOTS` JSON 数组传输；仅接受现存、无符号链接的项目内相对目录。重复、续训及评估沿用历史目录，当前选择不一致时拒绝继续。工作区 `K` 提供会话选择并检查 CLI 能力；尚未支持这些路径的操作由工作区明确拒绝。

项目级路径可通过 `K` 或 `config set-runtime-paths` 预览、按修订条件保存，并可通过配置历史恢复；新模型运行、显式库导入及批量装配读取项目默认值，会话选择优先。重复、续训及评估使用历史运行记录。当前支持范围以实际操作和 capability 为准，尚未完成所有操作及人工体验。

数据预览也读取项目或会话路径，在导入数据工厂、变换和 renderer 前应用搜索目录，并在生成清单中记录路径声明。自定义路径下暂不复用预览缓存，因为默认源码指纹未覆盖所有可选模块目录和工作目录资源；预览可能因此更慢。工作区使用能力协商拒绝不支持该行为的旧 CLI，worker 也检查专用 feature。路径声明不证明实际读取的数据或全部动态导入未变化；该路径尚未人工验证。

未显式选择 Python 时，数据预览核对当前项目配置中的解释器与 CLI 启动时的选择；不一致时拒绝执行，要求重新请求。显式选择优先；CLI 启动时记录项目 Python 选择及项目路径，若该选择随后被删除也会拒绝执行。旧工作台切换项目时根据目标项目配置更新解释器及对照快照；配置不可读或所选受管环境无效时不会继续使用上一项目的解释器。嵌入式调用等未提供快照的情况仍只能按当前非空选择检查。执行期间配置和外部环境也可能变化；此路径尚未人工验证。

未明确指定 Python 时，新运行优先采用项目配置中明确保存的解释器，再使用项目环境选择或项目 `.venv`，最后按当前 `PATH` 中目录的顺序发现可执行的 Python；不通过规范化解释器符号链接切换到基础环境。工作区 `e` 可选择任意解释器并经预览和修订检查保存到项目或移除；CLI 也支持 `config set-python --executable <路径或命令>`、`--clear` 和配置历史恢复。保存只记录选择，不验证解释器或安装依赖；输入路径及命令保存在本地项目配置中，不应包含凭据。显式会话 `--python` 优先于项目选择；续训、重复试跑和评估默认优先使用历史记录的 Python，用户显式选择其他解释器时续训会拒绝冲突，评估允许明确覆盖。旧记录没有解释器时才使用当前选择。环境检查和库清单使用项目选择，不擅自切回受管理环境。所选解释器失效时报告失败，不静默使用其他解释器。此功能尚未经过人工运行验证。

续训除了已有的运行报告设备对照，还在读取经摘要校验的 checkpoint 后比较其中可用的实际设备、后端和名称；不一致时拒绝恢复状态，旧 checkpoint 缺少观察字段则标记未知。`auto` 和可见设备索引在不同环境中可能解析到不同设备；即使这些字段一致，也不能证明物理设备、驱动或整个环境相同。用户工厂、模型构造和设备初始化可能在检查前已执行，无法回滚其副作用。该路径尚未人工验证。

显式库导入在所选解释器的独立子进程中使用本次选择的工作目录及项目模块搜索目录，并报告模块来源；合法 Python 模块名保持大小写，并由 Python 的标识符规则校验而非限定 ASCII；即使预置发行包的元数据不存在仍尝试显式导入，发行包状态不证明导入对象的归属；探测结果将第三方代码是否运行标为未知，并说明导入失败也可能已经执行初始化代码；JAX 额外运行时计算使用环境默认后端，不重写 JAX_PLATFORMS，会报告观察到的后端和设备，也可能初始化加速器；它不安装依赖，也不因此认定存在训练适配。相对解释器路径在切换子进程工作目录前按原项目上下文解析。

环境库导入和设备查询从同一次项目配置读取中解析项目 Python 与运行时路径，避免配置在两次读取之间改变时混用不同版本的选择；CLI 启动后如果发现项目 Python 与启动时选择冲突则拒绝操作。会话显式覆盖仍优先；执行期间环境和项目配置可能继续改变，此检查不构成环境快照。尚未人工验证。

新模型运行在解析模型与输入后再次读取运行时路径时，会比较两次配置修订；若原配置消失、解析时不存在的配置出现或修订变化则拒绝运行。未显式指定解释器且当前项目 Python 与启动时选择不一致时也拒绝运行。若输入解析没有读取项目配置，则没有对应的跨读取修订证据；检查完成后配置或外部环境仍可能变化。历史运行维持其记录的运行上下文。此路径尚未人工验证。

批量装配候选使用所选路径执行前向；自定义路径下提交必须携带预览返回的源码和路径联合摘要，其他尚未支持的装配操作拒绝该配置。快照运行不再主动将实时项目根目录加入导入路径；源码清单若观察到项目实时 Python 模块，会报告冲突，运行后观察到冲突时标记该运行失败。训练在每次实际写入检查点前也检查当前已加载模块，发现冲突则不写该检查点；不会回滚此前步骤或已存在检查点。运行中的动态导入可能在检测之前已执行，检查也不能覆盖自定义加载器、原生扩展、已卸载模块及非 Python 文件，因此这不是完整隔离或无副作用保证。已安装包和数据仍未由源码快照固定。其他装配操作和 CLI 独立配置仍需完成。

训练期间新观察到的模块若与已创建的源码快照清单一致，会单独记录而不自动视为源码变化；无法核对的新增来源仍视为冲突。新检查点记录整个源码快照摘要，续训时要求新快照摘要一致；旧检查点缺少该字段时维持原有检查，不能宣称具备这项完整快照对照。此摘要只涵盖快照清单，不涵盖依赖、数据及自定义加载器。

语义标记的绑定上下文记录自定义运行时路径的摘要；审计、监督预览和监督训练使用当前路径核对。默认路径下的历史标记保持原格式，自定义路径变化时需手动重新绑定。该摘要不能证明项目代码没有在执行中更改目录。

自定义监督函数的添加会显式执行导入，遵循工作区或项目选择的工作目录及模块搜索目录；内置规则的添加和只读列表不需要导入这些函数。使用规则前先核对固定源码及 Python 报告的目标导入位置，再导入并复核；快照训练时源码必须在快照内。查找子模块时可能执行父包初始化，已有导入、自定义加载器或并发变化也不能完全约束；已执行的用户代码不回滚。

工作区添加规则时先从保存的语义标记中选择角色和端口，并将读取到的语义状态修订传给 `rule add --if-state-revision`。后端持有语义状态锁读取和比较后才写入，标记重新绑定或其他规则变化会使本次操作冲突；未传该选项的旧 CLI 用法仍可使用。源码状态未变化不代表当前模型绑定已经过前向验证。自定义规则的导入发生在最终加锁比较之前，因此即使修订冲突也可能已有导入副作用。此路径尚未人工验证。

## 开发拓扑、路径身份与传输边界（M0-02）

### 支持矩阵

| 拓扑 | 编辑器 / 工作区 | CLI | Python、模型、输入与设备 | 当前边界 |
| --- | --- | --- | --- | --- |
| 本地单环境 | 本地主机 | 由编辑器进程直接启动 | 必须由用户选择或在该运行时中解析；可访问性逐项观察 | S1 首选范围；路径按该主机文件系统核对。设备不因路径可见而推断可用。 |
| SSH 内同机 | Neovim、CLI 均在同一 SSH 主机/容器内，用户通过远程终端使用 | 同一环境的本地子进程 | Python、模型、输入和设备均在远端进程实际可见范围内解析 | `localhost` SSH 已走查工作区前向、源码定位及后台用户循环断开、重连和恢复；客户端和服务端仍在同一台主机及文件系统上，独立远程主机和其他网络条件尚未覆盖。它不是本地 UI 调用远端 worker。 |
| 分离主机 / 容器 | 编辑器与 CLI 位于不同主机、容器或文件系统命名空间 | 远端 CLI/worker 或容器进程，生命周期可能独立 | 所在位置、挂载、设备及数据可见性各自未知 | 未支持/未知。当前 TUI 不建立 SSH 会话、不启动远端进程，也不做路径映射或传输。 |

判断拓扑时需分别记录编辑器主机/容器、CLI 主机/容器、项目根目录、Python 解释器、模型源码、输入数据、设备及运行生命周期；不能从一个可见路径推出其余资源位于同一处。SSH 终端中的同机 CLI 由用户在远端运行，其路径、进程和设备仍以远端为准。

```text
本地：编辑器/工作区 ──启动本地子进程──> CLI ──选择的解释器──> 模型 + 输入 + 实际设备
      └──────────────同一主机文件系统中的项目根目录─────────────────────┘

SSH 同机：用户登录远端 ──> 远端 Neovim/工作区 ──启动远端子进程──> CLI/Python/模型/输入/设备
         （以上均由远端环境解析；不是本地工作区的远程 worker）

分离主机/容器：本地编辑器    ×    远端 CLI/Python/模型/输入/设备
                         无隐式路径映射、SSH 启动或文件传输
```

可复现的人工走查至少固定并记录：编辑器与 CLI 版本及各自主机/容器；操作系统和文件系统边界；用户明确选择的 CLI、Python、项目根目录和工作目录；模型源码与输入在 CLI 进程中的规范路径；所选设备及运行时返回的实际设备观察；操作确认时机和运行 ID。检查 URI/不可映射路径时使用一个本地目录、一个 `ssh://` 或虚拟 scheme 项目标识、以及一个源路径身份不匹配的场景，确认启动前拒绝且不跳转/写入；断线场景必须记录请求是否已启动、是否取得回执，以及用原 run ID 查询的真实状态。具体已完成的局部场景及限制见[本地走查](acceptance/local-workspace-walkthrough.md)，这些前提不表示全部场景均已验证。

### 路径与身份

- 项目路径必须是 CLI 所在文件系统中的明确本地目录。`ssh://`、`file://`、编辑器虚拟 buffer URI 以及其他带 scheme 的 URI 不是本地路径；不得去掉 scheme、拼接项目根目录或凭同名目录猜测映射。
- 映射能力未实现。将来若加入映射，必须由用户显式配置并绑定两侧规范路径、文件身份（至少内容摘要及可用文件身份信息）、来源和有效期；读回后不匹配、不可解析、越界或链接目标不可信时，拒绝定位和写入并展示原始位置与原因。不能将路径字符串相同当成文件相同。
- 路径映射与运行上下文可显示主机/容器标识、项目目录和用户选择，但不得携带密码、token、密钥或配置文件内容。进程 stderr 会遮蔽由敏感名称环境变量承载且出现在 stderr 中的值；这只是传输层尽力脱敏，不是对任意用户代码输出、参数或后端报告的通用秘密扫描保证，界面不得把敏感配置原文放入路径上下文。
- 执行只作用于明确选中的 CLI/Python 和其报告的运行身份；连接、代码执行、复制、环境更改及设备选择均不得暗中发起或自动绑定。CLI 的确认与报告是执行动作和结果的权威，TUI 传输层不推断远端授权或设备身份。

### 断线与 S1

请求启动前失败须报告 `operation_started=false`。进程启动后发生信号中断、输出不完整、超限或报告无效时，结果是未知；不可据此认定任务已停止，也不可自动重试可能写入的动作。应使用已存在的 run/request ID 查询；没有可查询身份时，提示用户检查项目状态后再决定。进程退出且返回有效 CLI 报告时，按协议状态呈现结果。后台任务是否继续及清理情况以 CLI/监督进程的实际查询结果为准。

S1 拓扑准入限定为：本地同一文件系统，或之后经实际确认的 SSH 内同机运行。分离主机、容器挂载、跨主机路径映射以及跨主机 worker 均不作为 S1 能力。复现条件至少记录 Neovim/CLI 版本与位置、操作系统/容器、规范项目路径、所选 Python、输入/模型可见位置和设备观察结果；不得将未体验拓扑标为通过。localhost SSH 的后台运行与重连是有限观察，详见[本地走查](acceptance/local-workspace-walkthrough.md)；远程主机、容器和启动回执丢失时的网络断线仍未验证。

Layer 构造位置与源码候选使用所选 Python 的实际安装路径识别环境文件，不仅按 `target`、`venv` 等目录名排除源码。环境安装目录、项目元数据、版本控制目录和符号链接路径仍不允许自动修改；候选仍需通过源码唯一性检查、预览、确认和条件提交。骨架迁移按所选模块目录顺序寻找项目内源码，并核对 Python 实际导入的文件和加载器；有歧义或不受支持的加载方式会拒绝迁移。

批量源码计划支持在同一临时模型中先修改构造参数、再执行支持的容器结构操作，并对组合结果执行一次前向。混合计划按原始路径解释，要求 set 在结构操作之前；目标重叠、同一源码行补丁冲突、路径无法核对或过大时拒绝，不推断复杂操作顺序。预览使用内存中的候选模型，实际源码提交后仍在新 worker 重载并按事务规则验证；多文件修改不是瞬时原子可见，也不能撤销已执行用户代码的副作用。CLI 和 worker 分别协商混合事务能力；此新路径尚未人工验证。

工作区源码编辑可使用本会话选择的模型、代表输入与工厂参数，不必先写成项目默认值。预览请求的具体入口和参数随条件提交复用；输入摘要、项目配置修订、源码清单和候选补丁仍分别核对。会话选择在审核期间改变则停止提交；独立重验也比较会话选择。外部库、用户代码副作用、目标值及完整运行环境仍未固定，变更使用会话参数的路径尚未人工验证。

会话显式覆盖项目路径时，未单独指定工作目录会以项目实际目录覆盖保存的目录；源码编辑与批量装配预览按该实际目录核对路径身份，而不是把空选择误认为后端未记录目录。实际目录不可取得时仍不应将预览视为已验证；此路径尚未人工验证。

前向证据缓存的源码指纹覆盖明确选择的项目模块目录；如果观察到项目模块或模型源码不在可指纹化的扫描范围内，则不复用缓存。动态导入、自定义加载器以及未观察的外部依赖仍不能由这一检查完整覆盖。

缓存指纹逐块读取并检查文件读取前后的身份和元数据；文件在核对期间变化则停止复用。权重超过既定字节上限时不建立该缓存。上述检查不能替代文件系统级快照或保证捕获所有并发修改。

源码条件提交前后的清单核对也逐块计算摘要，并比较读取前后的文件大小、修改时间、路径及平台支持的文件身份；观察到变化或无法取得必要元数据时停止。它减少大文件的瞬时内存占用，但不能阻止读写之间或核对完成后的并发变化，也不是文件系统快照。此实现尚未运行验证。

运行对比单独展示记录的工作目录与模块搜索目录声明；新运行明确记录默认选择，旧记录缺字段时结果为未知。声明不同不一定代表实际目录不同，相同也不能证明运行期间的实际路径、导入模块或环境一致。

如果启动器中断后遗留的运行记录阻挡新任务，可先执行 `m-model runs acknowledge-unknown <运行ID>` 查看记录、checkpoint 与身份检查结果，并自行检查相关进程和日志。仅在接受仍可能存在未登记进程等不确定性时，才使用预览返回的修订执行 `m-model runs acknowledge-unknown <运行ID> --if-revision <修订> --acknowledge`；工作区运行列表也提供相同审核入口。新记录保存系统启动及 PID 命名空间身份；身份不一致时无法从当前环境检查原进程，须先核查原环境并明确接受风险，CLI 额外指定 `--accept-different-scope`。旧记录缺少身份时则须确认已在原环境检查，并额外指定 `--accept-unverified-host`。工作区在最终确认中说明对应风险。操作在锁内重核记录；同一命名空间内也会检查已登记 PID。它记录用户接受的不确定性和当前环境身份，保留运行文件，将状态记为 unknown 并解除新任务阻挡。它不会停止进程，也不证明训练已停止；当前仅在 Linux 提供此路径，系统启动与命名空间身份也不能证明未登记子进程不存在。

直接 Python 模型接缝可保存工厂和 JSON 参数，不要求先登记组件；接缝、参数及工厂路径使用 Unicode XID 标识符校验，所选 Python 会再次校验，Unicode 版本差异仍可能造成拒绝；工厂在所选解释器及运行时路径中构造，预览需实际前向。已登记组件继续核对版本锁；直接工厂没有组件版本锁，其外部依赖及未观察的动态代码不因此被固定。CLI/worker 对该格式进行能力协商；装配代码生成使用模块动态导入及字典形式的关键字传参，支持合法 Unicode 入口和作为接缝名的 Python 关键字。生成代码仍需按运行时实际签名构造并验证，尚未人工走查。

训练与试跑接受显式输入绑定；续训和相同工厂的重复试跑从历史运行继承绑定。重复试跑若更换模型、批次或训练入口，不把原入口的参数或模型接缝带给新入口；更换批次工厂时也不继承旧数据版本声明；切换到完整循环会移除历史独立批次及其绑定，明确切换模式时不沿用原模式的步骤参数，新检查点签名记录绑定并在续训时核对。旧检查点缺少绑定字段时沿用历史运行记录，报告该绑定没有检查点证据。导出包的 `resume_managed_steps` 对新检查点可使用匹配签名的显式绑定，旧检查点仅允许运行记录明确为自动绑定；自定义优化器须核对工厂、参数、类型和参数组与 checkpoint 身份；便捷续训开始前重新核对导出源码、支持文件、扩展文件、声明的运行时依赖版本及工作目录，缺失、不匹配或脱敏时拒绝。外部依赖和动态导入无法完全固定，用户也可自行恢复。上述链路尚未运行验证。
