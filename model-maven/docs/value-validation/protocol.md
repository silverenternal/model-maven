# Model-Maven 用户价值验证协议

**状态：研究方案已就绪；尚无参与者或观察结果。** 本协议定义后续配对观察。自动化测试、开发者自测、示例项目和本机计时不能作为用户价值证据。

## 目标与假设

验证 Model-Maven 是否能让已有复杂 PyTorch 项目的工程师更快理解一次真实模型调用并完成局部修复，同时记录为此付出的环境准备、适配和学习成本。研究不得以“能跑预设”替代复杂模型验证，也不得假设工具必然更快。

- **H1：** 在参与者自己的复杂模型任务中，工具能减少从开始诊断到得到正确、可解释的局部反馈的时间或操作负担。
- **H2：** 参与者能理解反馈覆盖的调用、输入和局限，并能安全完成 Layer 局部编辑、重载或回退；若无法完成，要记录在哪个边界退出工具。
- **反证：** 原工作流更快或更清晰；接入和迁移成本抵消收益；参与者误解探测覆盖范围；或复杂结构必须改写成受限预设才能使用。

产品范围和验收依据见 [`product.json`](../../product.json) 的 `value_validation`、`quality_and_acceptance.usability_targets`、场景 S3/S4、A6 与 V0/V1。已有的详细执行步骤和观察表见 [`cli-user-study.md`](../cli-user-study.md)；每位参与者使用本目录的记录 Schema。

## 参与者和任务

1. 招募至少有真实 PyTorch 模型维护经验、并能提供近期诊断任务的工程师。记录经验和模型复杂度，不以分类模板用户替代。
2. 让参与者选择近期会处理的真实任务，优先用原项目、原批次和原依赖。参与者可在本机操作；研究者不收集专有源码、原始样本、密钥或客户数据。
3. 同一参与者先使用其日常方法完成基线，再用 Model-Maven 完成同一目标或难度可比的目标。保留两种方法原有的 IDE、脚本、文档和助手；记录不能匹配的环境、初始化、帮助和顺序差异。
4. 首个里程碑只测首次有效前向诊断和局部修复，不强迫参与者先定义 loss、optimizer、trainer 或项目配置。只有参与者愿意时，继续观察 Layer CRUD、变体、步骤试跑和恢复。
5. 首位参与者用于发现流程问题和建立定性基线。后续会话交错方法顺序并记录熟悉效应；样本不足时逐人报告，不做显著性或普遍性结论。

## 观察和计量规则

- 会话前记录匿名参与者代号、Python/PyTorch、硬件、数据位置类别、已有工具/代码、缓存状态和任务目标。不得写姓名、联系方式、原始路径、数据标签、源码或凭据。
- 计时从开始准备开始，分别记录环境/依赖准备、迁移、首次 inspect、首次有效诊断、首次真实样本、修改后再次有效反馈和总耗时。明确冷启动或缓存条件；不要只比较命令执行时间。
- 记录手工输入次数、增改文件和代码行、重复运行、等待、提示、求助、取消、离开 CLI、未完成原因和是否必须改写用户代码。
- 以实际模型/批次复核诊断正确性。参与者需能用自己的话解释反馈范围、未覆盖部分、修改来源和保存状态，才计为成功；退出码和生成文件本身不算成功。
- 保留失败、无效批次、环境阻塞、不适用和放弃情况，不从分母中删除。没有测量的数据填 `not_measured`，不估算。
- 不录屏、不截屏，除非参与者对此单独明确同意。会话结束后由观察者移除可识别细节，再将匿名记录保存到 `results/`。

## 停止、保留和解释

参与者可跳过问题、暂停、停止或撤回尚未汇总的记录。研究者不得为了改善结果而人为削弱对照方法、注入无关错误、要求迁移到不必要的训练框架，或把失败改写成成功。

每份记录应包含条件差异和正确性复核。汇总只描述观察到的参与者、项目与任务；单人、预设或模拟结果不能支持市场规模、普遍提效或商业价值结论。原工作流胜出、用户误解、适配负担过高和复杂模型无法继续操作都属于有效结果，应转成产品修正或范围限制。
