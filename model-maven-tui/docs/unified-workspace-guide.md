# 统一工作区：从代码到一次前向

本文描述正在开发的工作树，尚未经完整人工走查，也不代表已发布的 0.1.0 包。普通 `m-model-tui` 启动和已有 Neovim 会话中的 `:ModelMaven` 使用同一套 Lua 工作区源码；启动器把源码写入临时 runtimepath，已有会话则从插件目录加载。两种入口都需要 Neovim 0.10 或更新版本和后端 CLI；项目操作还需要项目所选 Python 环境。工作区使用 Neovim 原生 buffer 和窗口，不设置主题、LSP、全局键位或个人选项；已有文件 buffer 可继续由当前会话和其插件管理。

在现有 Neovim 或 LazyVim 中遇到命令或交互选择异常时，可运行 `:checkhealth model_maven` 查看工作区来源、重复安装、命令冲突、交互输入提供者和 CLI 路径。该检查不会运行用户模型，也不能证明其他插件的行为兼容。

从终端启动 `m-model-tui` 时，按 Enter 从欢迎页进入工作区，按 `q` 退出。支持动画的终端会播放 Penrose 欢迎动画。加 `--skip-welcome` 可直接打开工作区。在已有 Neovim 会话中运行 `:ModelMaven` 会直接打开面板。

工作区默认显示较大的可移动 3D 模型预览；面板按 `8` 可隐藏或重新打开。拖动预览标题栏可移动窗口，标题栏的 `−` / `+` 可调整大小，`×` 可关闭；标题栏获得键盘焦点后也可用 `h/j/k/l` 移动、`+/-` 缩放窗口。点击图形区域进入交互：拖动空白处旋转，滚轮或 `+/-` 缩放，点击节点或连线查看，双击聚焦；按 `Ctrl-\ Ctrl-n` 离开图形输入返回编辑器。图中可见节点受窗口大小限制，可使用图内翻页查看其余节点。已保存的 `model-graph.json` 与尚未保存的画布草稿分别标记，预览只呈现声明，不代表模型已经运行或验证。没有图声明的已有模型可先运行模型检查；预览显示最近检查到的模块，并明确标记连线未知及已过期的快照。独立启动器内置渲染器；在已有 Neovim 中使用时，需要 `m-model-tui` 在 PATH 中才能显示三维图，找不到时仍显示文字拓扑；极小终端也会使用紧凑视图。空间不足时预览可以滚动，部分临时输入对话框可能暂时覆盖它。

## 从空白项目设计并运行

1. 在项目目录启动工作区，进入「新建模型」。选择空白、单路、双输入相加或待连接的残差骨架。首页若检测到已有图，会优先打开该图；旧版 `model-maven.json` 项目仍保留原来的编辑和迁移入口。
2. 在画布选择「+ 算子」，从当前 Python 环境或项目选择工厂，填写参数与输入输出端口。可在线上插入算子；从输出 `o` 拖到输入 `i` 创建分支。拖到空白处只改变布局，拖到已有块左侧或右侧则审核执行顺序；目前语义重排仅支持同一无分支单输入/单输出链。
3. 选择输入或输出节点，进入「连接数据」，配置 CSV、分类目录或已有工厂；预览会实际执行工厂。对每个输出配置损失、目标和权重；在训练设置中审核模式、入口和优化器。选择端口的「端口监督」可以编辑语义与草稿规则；草稿和引用不会自动启用，绑定、预览及训练启用需另行选择。
4. 使用「检查」查看未连接端口及声明冲突。菜单中的「联合审核图、源码和项目」可审核并开始可恢复的分阶段提交；也可分别保存图、生成源码及绑定数据。生成代码不会证明运行成功。选择「运行」执行真实前向，然后可准备试跑或训练；运行前核对解释器、设备、数据与监督。
5. 如需比较修改前后，先捕获输入。修改未保存的图后可重放该输入预览，但预览模型权重会重新初始化；保存和生成后可再次重放。输入一致不等于权重、环境或外部状态一致。失败定位给出可能的节点，仍需检查输入连接、参数和代码。
6. 要迁移项目，在图菜单选择「打包图项目」，审核源码、数据、环境文件和监督引用；目标项目需选择解释器并按需重新绑定。候选列表不保证发现动态导入和外部资源。

鼠标可点击块或拖线；无鼠标时使用方向键/`Tab` 选择、`Enter` 打开详情、`c` 接线、`M` 拾取并审核重排、`u` / `Ctrl-r` 撤销重做、`m` 查看操作。`F` 切换源码并排布局；选择代码窗口中的生成前向行后，回画布按 `x` 可定位到图节点。反向定位要求已保存的图与源码内容匹配；未保存 buffer 不会被覆盖。

### 中断与恢复

交付中断后，在图菜单选择「恢复记录的交付」：先查看图、源码和项目配置分别处于原版本、目标版本、冲突还是未知。继续时再次核对；若决定不继续，可归档记录，**归档不会回滚已经写入的文件**。该流程是多个条件提交，不是跨文件原子事务。未确认的训练启动先查看待确认请求与运行记录，不要重复启动；草稿恢复和外部修改比较不会自动覆盖文件。


显式图平面提供 `[O]` 源码入口：选择项目文件后，画布缩到源码窗口另一侧，源码继续使用原生 Neovim buffer 和当前配置。可以点击窗口或使用 Neovim 的窗口切换键返回画布；画布内 `[F]` 在并排与展开视图间切换。窄终端会缩小画布并保留横向滚动；这一布局仍需在实际终端及插件组合中走查。

选中组件的详情也可打开项目内组件源码，并使用同一并排布局。依据工厂路径列出的源码只是静态候选，不证明运行时实际导入的是该文件。

修改共享组件的参数或工厂前，确认框会列出受影响调用的名称；名称较多时可打开完整列表，再决定是否应用。将调用改为独立组件会创建新的实例声明，不会复制已有训练权重。

选中共享调用时，平面摘要显示共享调用数量；节点详情中的「查看共享此组件的调用」可列出并定位其他调用。这里描述的是图声明中的实例关系，实际运行和权重加载仍需验证。

图平面会根据草稿提示下一步，例如添加输入输出、连接未连接端口、保存、配置数据或准备运行。点击提示或按 `n` 可进入建议操作；接线时可先选未连接输入，再选择来源端口，系统会检查环路及已声明的端口契约。配置数据时先选输入或输出节点，再在详情中选择「连接数据」；需要训练时，可选择输出节点并在详情配置损失与目标。建议只反映当前草稿和已记住的保存基线，不代表磁盘、环境或模型运行已验证。

图已声明数据且已配置项目的输入状态可核对时，下一步会引导依次审核保存图和项目数据；两次写入分别确认，后一步取消时图仍可能已经保存。若项目尚未初始化或输入状态未知，先保存图，再按画布提示生成模型或审核项目状态。图声明、项目输入和会话覆盖可能不同，请在运行前核对画布状态。

图操作菜单中的「比较图与会话训练设置」并列显示草稿训练声明和当前项目、模型下最近的会话选择。图启动流程建议已保存的图设置，实际模式、入口与优化器仍由用户审核；显示历史选择不代表训练已启动。

完成训练参数与优化器选择后，可用「将会话训练设置载入图草稿」审核并复用该选择。它只修改图草稿，保留当前草稿的试跑步数（没有时使用 1）；保存图是单独操作。对于当前模型模块的受管 `step`，可选择保留固定入口或使用跟随所选图模型的生成步骤；后者的行为可能不同，参数仍需审核。

重新打开图画布时，如果发现本机恢复草稿，列表会展示节点数、连接数、文件修改时间和保存基线是否变化。恢复草稿不会立即覆盖已保存图；时间是本机文件时间，不能证明草稿更新于其他会话。

新的图恢复文件在可用时包含保存基线的原始内容。恢复时会先核对基线摘要与图格式；若基线可用，可对外部修改审核保守的三方合并。旧恢复文件或缺失基线仍可恢复草稿，但无法自动重建该基线。

连接分类目录图像时，如尚未声明损失，可先用输出节点名选择标签目标；之后训练前仍须为输出添加使用相同目标名称的损失。配置损失时可选择已声明的图像标签或 CSV 目标，也可手动输入其他目标。选择标签本身不会创建损失或验证训练。

从已配置分类项目以现有分类模型建立图草稿时，可选择携带已保存的监督文件引用；工作区会检查文件内容摘要和所选 CLI 的支持情况。引用不会自动把规则绑定到新图，仍需重新观察、导入及绑定；旧训练步骤不会自动复制到新图。

已保存的顺序模型可在没有现有图时，从画布入口审核原模型包装，或选择从声明生成可编辑层的草稿。两种方式保留原文件及声明快照，并带入受支持的数据、损失、训练声明和监督引用；训练、监督与工厂的实际兼容性尚未验证。可编辑草稿依据声明而非当前源码或权重生成，确认后才打开，运行前须核对。

选中图块后，平面顶部显示该块的组件参数、输出损失、输入数据或拼接轴摘要；点击摘要可打开详情。长参数和多项损失只显示部分内容，完整信息和编辑操作在详情中。

不使用鼠标时，可用方向键按空间位置选择图块，或用 `Tab` 循环选择；`Enter` 打开详情，`h/j/k/l` 移动已选块的显示位置，`c` 进入端口连接。空位置移动只调整布局；向已有块移动会先询问是否规划受支持的顺序重排。

工作区的 `E` 环境菜单可检查已选解释器、解析用户选择的依赖文件、在新的项目目录准备虚拟环境，以及检查或创建锁定 wheel 归档，或用归档离线创建新环境。解析和归档可能联网；准备环境会安装所选依赖，执行前会展示影响。此入口要求新环境目录尚不存在，不会自动绑定库或选择新解释器；wheel 归档的 ABI、系统和加速器兼容性需分别核对。离线创建尚待实际走查。

按 `e` 可选择会话解释器、项目环境或手动输入路径；安装 conda 时还可显式发现本机 conda 环境。候选未导入或验证，也不会自动安装依赖。环境菜单中的「查看执行位置与边界」显示编辑器主机名、项目路径、所选 CLI 和 Python 及观察到的容器标记；没有标记时不推断环境。这里显示的是编辑器上下文和选择值；包装命令或用户训练代码的实际执行位置仍需另行核实，不会尝试跨主机映射。

进入工作区后，空项目可点击「新建模型」或按 `n` 打开模型画布。空状态首先提供自由图画布，可从基础结构开始连接分支、多输入和自定义算子；已有图声明时可继续打开。也可选择顺序结构、二分类或双输入回归示例。顺序画布中点选编码器，可在属性区添加网络层、调整顺序、修改参数或移除层；画布会显示每层执行前后的特征宽度。内置层接收展平后的输入，动态轴在进入层之前取平均。可选层由当前 CLI 提供，包括 Linear、ReLU、GELU、LayerNorm 和 Dropout。自定义组件候选来自项目的静态扫描和已注册的组件。支持发送鼠标事件的终端可以用鼠标操作，也可用 Tab 和 Enter 导航。较窄的窗口将属性放到画布下方。

以下 `model-maven.json` 和顺序编码层操作描述的是旧版顺序构建器，不适用于上面的 `model-graph.json` 自由图流程。

对已保存模型，画布中的「载入项目输入」可将当前工厂、绑定和参数加入声明；「编辑项目输入」打开项目配置，保存后回到画布重新载入；「从声明移除输入」只移除可复用声明，保留当前项目的输入配置。点击「审核并生成」查看声明文件、工作区配置和生成的 Python。确认保存后，结果页可以直接运行首次前向、接入 CSV、继续编辑画布或打开生成的 Python。前向使用当前选定的输入，运行前会显示所用环境并请用户确认。 保存项目输入后可直接在结果页选择预览或前向；预览结果也可继续使用当前选择的输入运行模型。 前向失败时，如果项目有已保存的模型声明，结果页可以直接打开画布检查和修改声明；重新生成后需要再运行前向。 工作区面板可以用 `[1]` 捕获输入并运行前向、`[2]` 重放、`[3]` 删除快照；创建或更新结果页也可选择「捕获输入并运行前向」，即使该前向失败也保留输入快照；修正画布并重新生成后，选择「重放已捕获输入」可核对同一输入。快照包含输入值，可多次重放；主动删除、替换快照或关闭工作区时尝试清理，异常退出可能留下临时文件。相同输入不代表权重和环境一致。成功前向的结果页显示观察到的输出，并提供模块浏览、端口标记和训练试跑入口。

已有 `model-maven.json` 的项目可点击「打开模型画布」继续编辑。重新生成前，审核页会展示声明变更和即将激活的模型入口。确认后 Python 生成到独立版本文件，保留以前的源码和手工修改。项目已有真实批次工厂时会保留该工厂、绑定方式和参数，修改输入或输出后应重新运行真实数据验证。项目已接入自定义模型入口或模型工厂参数时，可在新目录复用声明，再从源码入口接入现有逻辑。

编码器层堆栈支持插入自定义 `module:callable` 工厂，并设置 JSON 参数与声明的输出宽度，可与内置层排序组合。 可从项目源码的静态候选中选择，或手动输入；候选优先按会话或项目保存的模块目录给出名称，也会提供项目根目录下的替代导入名称。候选只反映名称，尚未导入或验证。工厂参数可逐项添加、修改和删除，也可用 JSON 批量编辑。工厂在模型构造时从用户所选 Python 环境导入，必须返回 `torch.nn.Module`；工具不会安装依赖。输出宽度是用于后续层的声明；前向会检查该层返回二维张量，批次大小不变且特征宽度与声明一致。工厂的其他兼容性仍须通过实际前向验证；参数规模限制不包含自定义工厂内部的参数。

已保存模型的编码器、融合和输出模块属性区提供「打开组件装配」，可以继续配置支持的项目组件和参数。单项装配操作会使用画布中选定的节点，接入组件时可选择已注册组件、静态发现的项目工厂或手动输入；候选在发现时尚未执行，预览会核对已保存模型的实际接缝。装配中的组件若与画布声明不同，可在画布选择「载入已保存装配」，再审核并生成。被项目组件替代的内置编码层会从草稿中移除，同一组件的已保存参数会保留。画布无法表达的接缝会提示用户检查装配。

组件参数可在画布属性中编辑，并会写入 `model-maven.json`。从其他目录重建时，需同时提供组件源码或已注册的对应版本。参数可能提交到版本库，不应放入密钥。

组件编码器的属性中可以声明输出宽度，供默认融合与输出头使用。从内置层栈同步到组件时，画布会带入原层栈的最终宽度作为待核对的值；组件的实际输出需要通过前向验证。若组件改变了宽度，请在生成前修改该值。

可将 `model-maven.json` 提交到 Git，其中包括输入、动态轴、输出头、接线和选择的工厂。在新目录运行 `m-model scaffold --recipe /path/to/model-maven.json --json` 获取预览。审核后以相同命令加上 `--apply --if-plan <plan_revision>` 即可重建骨架。选择项目工厂时需一并提供它的源码，选择注册组件时需准备对应版本。

[浏览器交互原型](model-builder.html) 使用同一组拓扑节点、网络层和属性，支持打开已有声明、审核修改并下载新声明。内置编码器是有序层栈，任意分支、残差和自定义拓扑仍可通过项目组件和 Python 实现。

### 安装到普通 Neovim

将本仓库的绝对路径加入 Neovim 配置（例如 `init.lua`），并按需设置 CLI：

```lua
vim.opt.runtimepath:prepend('/absolute/path/to/model-maven-tui')
require('model_maven').setup({ cli = '/absolute/path/to/m-model' })
```

`cli` 也可写为 PATH 中的命令名，例如 `m-model`；`python` 可选，用于为工作区指定会话 Python。随后在项目中运行 `:ModelMaven`，或用 `:ModelMaven /path/to/project` 明确选择项目。无参数时会从当前文件向上查找 `.model-maven` 或 `.git`，找不到时使用当前目录。`:checkhealth model_maven` 可查看 Neovim 版本、配置 CLI 和实际加载的 Lua 文件位置。

### 安装到 LazyVim / lazy.nvim

在 LazyVim 的 `lua/plugins/model-maven.lua`（或 lazy.nvim 的插件 spec 文件）返回本地插件 spec；将目录替换为本仓库位置：

```lua
return {
  {
    dir = '/absolute/path/to/model-maven-tui',
    name = 'model-maven',
    main = 'model_maven',
    cmd = 'ModelMaven',
    opts = { cli = 'm-model' },
  },
}
```

`cmd` 让 lazy.nvim 在首次调用 `:ModelMaven` 时加载插件，`opts` 由 lazy.nvim 传给 `require('model_maven').setup(opts)`。本地 `dir` 不会自动安装依赖或改动用户配置。插件仅定义 `:ModelMaven` 命令；若该命令已由用户配置占用，会提示并保留现有命令。工作区快捷键只作用于自己的面板 buffer。关闭面板会恢复原 buffer 或关闭工作区分屏，不会主动关闭用户已有 buffer。

在已有会话中打开工作区时，相对 CLI 路径按当前编辑器目录解析；可在 PATH 找到的命令也固定为该次会话的可执行路径，再以项目目录启动进程。如果命令在打开时找不到，操作会提示安装或更新 PATH 并重新打开工作区，不会在项目目录重新搜索同名命令。切换 PATH 后需关闭并重新打开工作区；路径固定不代表文件内容或运行环境固定。

在工作区按 `s` 切换语言时，面板操作和仍由工作区管理的按键说明会一起刷新，供 Neovim 的按键提示插件读取；用户自行改过的映射不会被语言切换覆盖。

在监督规则列表中打开一条规则后，可点击「复制到其他标记」或按 `c`，将已有规则复制到其他语义标记；确认时会检查规则状态修订，并保留原规则。自定义规则会保留固定的源码身份与参数，复制时不重新固定源码；新目标的绑定和规则源码仍需通过监督预览检查。

端口监督面板中，历史训练结果若观察步数为零，会显示「本次运行未观察到」而非把零违规当作通过；缺少观察步数则显示状态未知。

模型重新生成或组件变化后，监督预览如果报告绑定过期，可在结果页选择「选择需要重新绑定的标记」，再运行前向，并从前向结果选择「将所选标记重新绑定到观察端口」。重新绑定前请核对端口、语义及规则；原有规则会保留，之后可再次预览。

准备过训练入口和参数后，可在已保存模型的画布中选择「载入训练设置」，审核并写入 `model-maven.json`。重新打开工作区后，选择相同训练模式时，入口与参数会作为可编辑默认值，输入提示标明来自已保存声明还是本会话；不会自动执行训练。请结合当前模型核对入口和参数。可在画布移除训练声明。声明不包含设备、优化器、监督或训练步数，入口所需源码与环境需另行提供，参数不要填写凭据。选择当前模型模块的示例 `step` 时，声明会使用 `$model:step`，在运行时解析为当前 `module:model` 对应的 `module:step`，以便重新生成后跟随新构建。命令行可显式使用 `m-model try --training-recipe model-maven.json --steps 1` 或 `m-model train --training-recipe model-maven.json --steps 100`；不能同时指定其他训练入口、重复试跑或续训。

运行记录菜单可对历史训练试跑选择“重复训练试跑”：先审核历史输入，再选择关闭监督或审核并启用当前规则。操作需要支持历史输入摘要的 CLI；摘要只固定记录的输入声明，不保证外部数据、源码和依赖未变化。训练续跑仍使用单独的检查点恢复流程。 也可选择“使用记录中的训练入口与参数”，确认后在当前会话准备同模式试跑或正式训练时作为可编辑默认值。仅接受当前模型的完整、未脱敏入口与参数；设备、优化器、数据、监督和步数仍需单独选择。

模型、输入、评估器和训练入口的普通参数可以使用 Unicode 或自定义关键字名称，最终是否被接受由实际 Python 可调用对象决定。工作区使用 `NAME=JSON` 传参，因此参数名目前不能包含等号或控制字符；自定义优化器等专用协议可能有更严格的标识符要求。

面板展示会话输入绑定，或当前项目保存的绑定及其来源。`P` 中使用项目绑定会保留项目配置；也可以直接选择“当前项目输入使用自动绑定”。后者经确认后将当前工厂和合并后的参数作为会话覆盖传给 CLI，参数值可能出现在进程参数和运行记录中；项目配置不会因此改写。使用会话输入时，可在同一菜单恢复项目输入、参数和绑定；此前的会话工厂草稿仍保存在内存中。

创建模型时，输入声明省略 dtype 会让生成的合成批次在执行时使用当前 PyTorch 默认浮点类型；显式指定的 dtype 则由该运行时解析。如果代码在模型构造和批次执行之间改变默认类型，二者可能不匹配，应明确指定 dtype 或调整用户代码。旧 CLI 不支持此约定时，工作区要求显式填写 dtype；计划中的输入名、形状、动态轴和 dtype 必须与所填声明一致才能继续。

当前骨架最多可声明 32 个输入和 32 个具名输出，每个输入最多八个非批次维度；项目配置同时最多保存 32 个组件注入接缝，超过该组合需要直接编辑用户代码。更多输入、输出或维度不会自动证明模型能在目标环境中运行；生成受特征数限制，工作区仅允许提交可完整审阅的计划。

新骨架的输入和具名输出可使用 Unicode 名称，需要兼容 CLI 支持。名称要求符合标识符字符规则、不能以下划线开头且不超过 48 字节；Unicode 名称按原始字符串作为字典键和接缝参数传递，相同原始名称不能重复，视觉相近或正规化后相同但字节不同的字符串不会自动合并。Unicode 输入的合成批次动态维度通过具名参数字典读取；现有 ASCII 骨架接口保持原样。此路径尚待人工验证。

使用自定义运行时路径时，工作区会先检查 CLI 是否支持这些路径。可取消的操作在检查期间收到取消请求时不会启动模型操作；操作已经启动后，取消只是请求中断，需查看最终回执确认结果。

导出使用历史运行记录中的环境和源码快照，不把当前会话的模块目录覆盖到历史运行；环境记录缺失时可能启动记录的 Python 收集信息。历史 Python 缺失时不会擅自使用 PATH：无扩展包时环境可保持未知，有扩展包时可明确选择会话 Python 进行核验；这不证明它等同于训练环境。训练或续训若在进程启动前被工作区明确拦截，会清理该次待确认标记；如果清理失败，仍需检查标记。进程启动后的未知结果仍应通过运行记录核查。

历史导出不依赖当前项目的 Python 默认配置；当前配置损坏时，检查结束后仍可从运行记录发起导出，检查点和所需扩展仍须通过各自的校验。

项目的虚拟环境配置损坏时，工作区仍可通过只读装配配置检查读取项目状态，再用 `e` 明确选择 Python 或修复环境。静态组件查看、Layer 目录和源码骨架不需要启动 Python；各操作仍会检查自己实际使用的项目配置。

面板按 `s` 选择跟随系统、English、简体中文或繁體中文；同一 Neovim 会话中打开的工作区会一起刷新。保存偏好时会检查文件是否在读取后变化，发现冲突则只在本会话生效并提示重试；该检查不是文件系统事务。后端诊断和用户代码输出可能保留原语言。

在已有 Neovim 会话中，`:checkhealth model_maven` 检查 `setup()` 配置的 CLI 是否可发现，不导入用户模型；某次 `open()` 的单独覆盖、项目依赖与实际运行能力需要另行检查。

打开工作区后，源码仍是你的 Neovim buffer。面板最上方显示当前建议、结果和相关快捷键；`f` 打开可用 `/` 搜索的操作列表，`x` 展开全部操作，`?` 查看内置帮助。使用 `Ctrl-w` 加方向键在窗口间移动，报告页的 `q` 关闭当前报告，面板中的 `q` 关闭面板；命令启动的独立 Neovim 会话可输入 `:qa` 退出，未保存修改时 Neovim 会提示。项目、CLI 和 Python 在 Neovim 所在主机执行；用户代码默认在项目根目录运行，也可按下文所述为支持的操作选择运行目录。

Layer 源码修改保存后，已打开的源码可能仍显示旧内容。按 `V` 重验时，工作区会先引导选择需要处理的文件；若 buffer 没有未保存修改且标记为待载入，可选择先查看，或明确选择从磁盘重新载入，然后返回面板再按 `V`。选择载入前工具会再次核对 buffer 和项目；有未保存修改或状态不明确时，请自行检查和处理，工具不会强制覆盖。已在本地走查单个未修改 buffer 的载入和重验；多 buffer、并发修改及不同插件自动命令仍需验证。

面板依据打开它的实际窗口宽高选择侧栏或底部分屏。源码窗口窄于 60 列且当前普通 buffer 可安全隐藏时，面板与源码在同一窗口切换；按 `z` 返回源码，对同一项目执行 `:ModelMaven` 返回面板。特殊 buffer 等情况会尝试分屏，使用 `Ctrl-w` 导航；无法分屏时会报告错误。工作区不主动放大源码窗口；不同尺寸和用户窗口布局仍待人工验证。

从观察结果定位源码时，工作区优先聚焦已显示该文件的窗口；否则会复用最近的普通、未修改源码窗口并保留原 buffer；遇到未保存内容或特殊 buffer 时尝试新开分屏，空间不足会报告。打开后会再次检查文件摘要与当前焦点，若打开期间发生变化则不跳转行号。跳到已核对的位置前会设置 Neovim 的前一上下文标记，可用 `''` 回到该文件先前的光标位置；这是原生编辑器标记，后续跳转可能改变它。

## 接入已有模型

1. 在项目中打开工作区。按 `F` 静态查找顶层函数和类，可按名称、文件、角色或模块目录筛选，并连续选择模型、输入和训练入口；对工具不认识的名称，可以自行指定角色。候选未导入或验证；包搜索路径、工厂参数及返回类型仍需要用户确认。

静态查找优先依据所选模块目录的顺序生成入口名，再考虑项目根目录。例如选择 `src` 后，`src/pkg/model.py` 的候选可显示为 `pkg.model:...`。同名模块、包初始化代码和自定义加载器仍可能改变实际来源；请通过所选 Python 的运行结果核对。
   对 `src/package/model.py` 一类布局，可先按 `K` 将 `src` 加入项目模块搜索目录，再按 `F`；扫描会优先考虑所选目录，即使它的名字属于默认跳过的目录，并额外给出基于该目录的 `package.model:…` 候选。扫描范围有上限；旧 CLI 不能优先扫描时会提示。候选仍需实际运行后才能确认导入来源。
2. 若项目没有合适的工厂，按 `N` 创建可编辑的适配器草稿，选择项目根目录或当前已选择的项目模块目录，填入自己的代码并用 `:write` 保存；草稿不会自动覆盖已有文件。模块名允许 Unicode，工作区只检查路径分隔符等基本格式；CLI 会检查标识符语法，所选 Python 在实际导入时进一步验证。不可用、重复或经过符号链接的模块目录不会列为保存位置，请通过 `K` 检查。同名模块可能被搜索顺序中更靠前的路径遮蔽，选择工厂不证明导入来源。模型工厂须返回模型，输入工厂可返回 `{"args": [...], "kwargs": {...}}`。按 `?` 查看完整示例。
3. 按 `a` 填写模型和输入的 `module:callable`，查看配置预览；在报告中按 `a` 继续并确认后保存。已有项目的默认模型和输入可分别用 `Q`、`S` 预览并条件保存。保存模型时须决定是否保留原有装配注入，保存本身不验证模型。
4. 按 `e` 选择本次会话使用的 Python：可使用项目默认值、手动输入，或从当前会话、`VIRTUAL_ENV`、`CONDA_PREFIX`、`UV_PROJECT_ENVIRONMENT`、项目 `.venv` 和 `PATH` 的可执行候选中选择。没有显式选择时，新 CLI 优先使用已保存的项目环境或项目 `.venv`，再按 `PATH` 顺序发现 Python；发现本身不会执行解释器。候选仅检查路径和可执行状态，尚未运行验证；相对环境变量和 PATH 候选在当前编辑器目录解析为绝对路径并保留符号链接，手动填写的相对路径则按项目目录解析；按 `E` 检查环境或明确导入所选库。工具不自动安装或绑定依赖；检查报告展示解析到的解释器。

`E` 的显式导入可填写内置库 ID，也可填写其他 Python 模块名（例如 `my_package.submodule`）；导入会执行模块初始化代码。未知模块不自动推断发行包或专用后端，导入结果只说明所选解释器中这次导入的结果。

环境清单来自所选解释器的发行包元数据；元数据存在并不等于模块可导入或已有专用适配器。如果项目已保存的环境不可用，请修复项目环境配置或用 `e` 明确选择另一个解释器，然后重新检查；运行模型不会自动回退到其他环境。

环境清单报告先展示少量已安装条目和后端遗漏数量；按 `s` 可在本次报告的发行包中搜索、查看详情，或明确填写模块名并确认导入。按 `i` 可向所选环境查询一个完整的发行包名称，结果不受清单展示上限影响，但仍要启动 Python。报告内搜索只覆盖本次有界报告；发行包名与模块名可能不同，环境也可能在报告生成后发生变化。

按 `K` 可为当前会话选择已有运行目录，以及用 JSON 数组指定有序的项目相对模块搜索目录（例如 `["src"]`），或恢复默认。检查、前向、Layer 编辑、批量装配、试跑、训练、评估和显式库导入可携带这些路径；部分其他操作尚不支持，界面会阻止其静默使用默认路径。自定义路径下保存批量装配需要核对预览时的源码与路径摘要。导入报告包含所选解释器、路径和模块来源；来源是本次导入的观察，不代表后续运行一定相同。历史训练的路径必须与所选上下文一致；变更后应重新观察。目录选择不会安装项目或固定第三方依赖。

`K` 也提供逐个添加、移除和上下移动模块目录的交互。顺序越靠前，所选目录在 Python 搜索路径中的优先级越高；调整先只影响当前会话，需要使用“将当前路径保存到项目”才会持久化。已加载的模块和自定义导入机制仍可能影响实际导入来源。

执行用户代码或准备训练的确认窗口可按 `e` 修改当前选择，选择可用的 Python、路径、模型、输入或参数入口；修改后需要重新发起原操作并再次检查确认内容。历史运行和运行时检查仍使用各自的上下文，不提供该快捷入口；退出确认不会启动操作。

初始化项目、创建模型骨架以及保存默认模型、输入时，工具生成或写入项目文件，不运行工厂；这些操作可在选择会话路径后使用，并始终以项目根目录定位文件。`K` 可预览并将当前路径保存为项目默认值，也可仅在本次会话覆盖，或重新使用已保存的项目路径。保存使用配置修订保护，不验证导入；绝对运行目录换机器后可能需要重新选择。历史运行继续使用其记录的路径。

按 `P` 可以编辑当前会话的模型或输入工厂参数覆盖：输入框带出已有 JSON，修改所需字段即可；输入 `{}` 清除对应覆盖。参数值可能出现在进程参数和记录中，不要填写密钥。覆盖只影响当前会话，保存为项目默认值需使用相应的默认配置操作。

切换模型、输入、Python 或工厂参数会使先前观察过期；项目配置刷新发现修订变化或无法核对时也会使结果过期。旧报告仍可查看，但需要在新上下文重新运行才能作为当前证据。

在面板按 `U` 可选择理解、修改、监督或训练目标，也可填写自己的目标；只保存在当前工作区会话。选择内置目标后，观察到模型时首页会调整建议操作；自定义文字不自动推断意图。查看其他报告后，可按 `h` 重新浏览同一上下文中上次前向的观察，无须重新运行；这不是新前向，标记或重新绑定仍需执行新的前向。上下文或 buffer 变化时不能恢复观察，外部数据和依赖仍可能变化。成功标记、保存规则和预览后，首页会依次提示后续操作，无需事先选择监督目标。预览报告的成功不等于规则通过，也不代表完整数据覆盖。异常和需要重验的状态优先显示，选择目标不会运行代码。

按 `P` 可设置当前会话的输入绑定：单个值、位置参数、关键字参数或显式 args/kwargs 封装。切换模型或输入工厂时，参数和输入绑定不会带给另一个工厂；同一会话切回原工厂时可恢复其草稿，关闭工作区后草稿不保留。使用项目默认输入时也可选择项目默认绑定。需要持久保存时使用 `S` 审核并保存项目输入配置。绑定选择影响支持会话输入的模型操作和训练，不改变用户工厂代码；装配配置编辑要求先清除会话覆盖。

模型创建结果页提供「接入 CSV 数据」，工作区也可以按 `Y`。创建数值 CSV 适配器 `model_csv.py` 后，可继续配置路径、一个或多个模型输入及其列、目标和批次大小。输入和目标支持运行时解析的 dtype 与不含批次维度的形状（`[]` 表示标量），也有浮点向量和整数类别索引选项。确认参数后可以预览输入，或选择「保存输入到项目」，核对配置变更后确认保存。仅用于本次会话时可直接返回工作区；按 `j` 预览输入，按 `S` 可再次进入保存流程。无目标推理需要适配器支持，旧版或用户修改的适配器可能需要调整。支持的 dtype 由所选 PyTorch 运行时决定，复杂或变长数据可以修改适配器或接入自己的工厂。

选择捕获并重放输入时，源码保存后快照会保留至独立重验匹配通过或工作区关闭；重验会重放快照并核对输入摘要。快照含输入值，异常退出可能留下临时文件。源码修改后的独立重验会对照预览时的会话输入绑定；即使输入内容摘要相同，绑定发生变化也会标为上下文不同，不会自动关闭待重验状态。

如果工作区重新读取项目配置时发现默认工厂已改变，会按工厂切换会话草稿；显式选择的会话工厂继续保持。保存项目默认工厂后使用刚保存的配置，不会自动叠加该工厂的旧会话草稿。

保存当前模型或输入为项目默认值时，表单预填对应的已有参数及会话覆盖；输入绑定的当前选择排在首位。若填写的是另一个工厂，则不会携带当前工厂的会话参数。保存前仍需检查预览，参数会写入项目配置。

从零开始时，按 `n` 输入一个或多个模型输入及可选的具名输出；单输出可选择特征数和回归或分类示例损失，可选择默认骨架或自定义 Python 模块名和已有输入工厂。输入可使用 `name:dtype=形状` 声明所选 PyTorch 环境中的 dtype；规划只检查名称格式，实际执行时才解析类型和创建张量。输入形状中 `?128` 将该轴声明为可变，128 是合成样本的代表长度；默认骨架在编码器输出上按对应轴求平均再展平，不验证自定义编码器是否保留了轴的语义。若编码器改变维度或需要保留原输出，应调整源码或选择支持的原生编码器输出模式。具名输出可使用 `score=1:mse@0.5;class=3:ce` 分别指定宽度、示例损失和可选权重；示例损失不是对真实任务的验证。查看生成计划、输入来源与源码，再决定是否创建。选择已有工厂时可同时指定输入绑定和 JSON 参数，预览确认后参数写入项目配置，请勿填写密钥。已有工厂不会在创建时执行或验证；示例输入和目标不等同真实数据或训练结果。创建回执中按 `e` 打开生成的源码，或按 `p` 发起首次前向；运行前仍会检查项目上下文并要求确认。也可返回工作区使用 `A` 调整支持的组件与接线。在同一会话按 `y` 试跑时，界面可建议刚创建的示例步骤；请先检查它的损失和目标是否匹配所用输入，尤其是选择了已有输入工厂时。建议不会自动保存为用户的训练配置。

`A` 中也可选择生成可编辑的 Python 适配代码，并指定项目内的新文件。该操作会执行项目工厂、在有输入时前向并独立重建验证，不覆盖现有文件；生成代码仍依赖用户的工厂和环境，不包含训练权重。报告区分重建、前向及两次观察到的输入对照；生成后用 `o` 打开源码检查，当前生成回执仍有效时路径会预填。界面在打开时尽力将磁盘内容与生成内容摘要比较，发现差异或无法检查时提示；已有未保存 buffer 也会提示。检查不能排除后续并发修改。无代表输入时不会执行前向。

使用 `A` 接入单个组件时，可输入工厂的 JSON 参数对象，例如 `{"width": 6}`；留 `{}` 使用工厂默认值。参数可能出现在进程参数和项目记录中，请勿填写密钥。预览会执行用户代码，只有审核并确认后才保存；一次调整多个接缝仍可使用批量装配。

选择输入工厂后，按 `j` 可审核工厂参数、选择最多预览的样本数并生成批次结构摘要。使用项目默认工厂时表单包含项目参数和会话覆盖；明确选择会话工厂时只带入会话参数。预览样本数限制展示范围，不限制用户工厂内部加载或生成的数据。它使用当前 Python 和支持的运行时路径，执行工厂并在项目 `.model-maven/previews` 写入本地预览产物；报告展示样本数、复用状态及本地文件路径，产物可能包含敏感数据。预览展示采样后的工厂输出，不验证批次绑定到前向的方式，也不等同于训练集或模型前向验证；工具不会自动打开或传输文件。

已有 Dataset 工厂可按 `J` 填写入口、参数、切分、样本数和可选采样种子并预览摘要；没有切分时可留空，需要 CLI 支持无切分预览。增强可以选择按切分自动、训练增强、评估增强或不使用项目增强；自动规则将 train 映射为训练增强、其他非空切分映射为评估增强、无切分不自动增强。显式选择需要新版 CLI。采样种子留空使用 CLI 默认值，工厂参数可有不同的 seed，工厂或外部数据源的随机性不能由采样种子完全固定。流式数据可填写扫描上限，采样仅覆盖扫描窗口，不代表整个数据集。工厂本身仍可能执行其他读取或产生副作用，参数与预览产物可能被记录，勿填写密钥。无切分、自选增强和种子路径尚待人工验证。

无参数工厂可选快速预览：不指定切分、不选择项目增强，使用 CLI 默认采样种子并请求最多 12 项；种子可能传给工厂。开始前会展示影响并要求确认，样本数不限制工厂内部加载。需要工厂参数、其他切分或采样方式时选配置预览。快速路径尚待人工验证。

预览报告区分采样种子与数据集工厂是否收到 seed；直接获得的数据集实例或自定义适配器可能无法确认。大于 Lua 可精确表示范围的采样种子会提示无法精确显示，输入时的十进制字符串仍直接传给 CLI；具体行为尚待人工验证。

装配菜单会提供已保存的组件接缝供选择；在创建骨架的同一会话中，还会提供创建计划声明的编码器、融合和预测头接缝。如果当前模型报告包含模型自身声明的输入路由，也会提供其中的接缝名称。单项和逐步组合的装配入口都提供这些候选，也可以手动输入其他接缝；输入接线可选择模型声明或同会话创建计划中已知的输入，编码器输出可选择保留原始输出或展平。各项均标明来源。这些只是配置、创建计划或模型自声明的提示，不是对当前模型全部可接入位置的发现或验证；接缝是否适用仍由预览时的实际构造和前向决定。可直接填写项目 Python 工厂及 JSON 参数，无需先登记组件；参数写入项目配置，请勿填写密钥。已登记组件仍核对版本锁；直接工厂没有组件版本锁，依赖实际源码与运行环境，保存前仍需审阅预览。

## 观察、定位和修改

按 `U` 可选择“检查模型端口契约”作为本会话目标；完成前向后首页会引导创建或运行契约。按 `X` 可在原生 buffer 打开契约 JSON、创建空白契约草稿，或者选择已保存文件对当前模型和代表输入执行前向检查。草稿不会覆盖现有文件；也可从当前新前向的根输入和输出生成 Tensor 端口候选。先用 `v` 选择已观察模块，也可为该模块创建契约草稿；它取第一次记录的调用，而契约运行时会检查每次观察到的调用。候选只反映该次样本，包含固定批次维度，需自行调整或使用符号维度；非 Tensor、歧义、截断及超出上限的项会省略并提示。审核并保存后使用；默认只检查真实前向，可自行开启静态推演。没有声明检查项的契约显示为不完整，而不是验证通过。运行前会检查文件是否可读、JSON 格式和已打开 buffer 的未保存修改；确认后 CLI 会在启动 worker 前核对文件，worker 读取时再次核对相同的 SHA-256；如果两次核对之间发生变化，worker 在导入模型和输入工厂前拒绝请求；Python 启动钩子可能已执行。核对后本次使用已加载的契约对象。结果页显示契约摘要和核对状态、各端口状态、未知字段、部分不匹配及覆盖范围；按 `b` 打开当前契约文件修改，文件可能已不同于报告；模块检查有可核对的调用路径时可按 `d` 在当前模型中检查或预览源码修改；若记录的项目源码身份明确，也可核对后打开实现。相关模块不一定是根因。按 `J` 查看完整报告；本次结果不能证明未执行的分支。

通过 `F` 静态发现并选择模型入口后，`o` 会优先建议对应的项目源码文件，仍可自行输入其他路径。该文件只是名称扫描得到的候选，不能证明运行时导入了它；修改后保存并执行新前向，才能观察当前行为。切换入口时，会话参数草稿按工厂分别保留。

先保存项目中需要运行的修改。按 `i` 检查模型，按 `p` 使用当前代表输入执行真实前向；两者会运行项目代码并要求确认。结果页显示观察范围和诊断，`J` 打开完整结构化报告。失败时，若报告提供最后观察到的调用，按 `d` 可选择模块检查、重放或预览修改；最后调用不一定是错误根因。

错误或传输失败报告中可按 `s` 选择 Python、运行时路径或环境菜单，无需先返回面板。环境菜单可为本次会话选择 CLI：用户明确同意后执行候选的接口检查，核对版本再决定切换；接口检查不能证明可执行文件之后不变。切换不修改用户配置，已有观察将过期。请先阅读诊断：错误不一定由环境造成；更改上下文会使此前结果过期，需要重新运行。

前向报告分别展示 worker 在模型构造前、构造后和观察结束后的工作目录；项目代码可能在这些时间点之间改变目录。若复用了历史前向证据，这些目录描述的是当前 worker 的观察点，并不证明历史前向的每一次目录访问。运行目录可通过 `K` 在当前会话中明确选择；观察点不能证明项目代码在这些时点之间没有更改目录。

失败报告提供项目调用栈时，`g` 核对文件后打开选定位置；`l` 将当前可核对的位置放入源码窗口的新 location list，在该窗口使用 `:lopen`，也可使用已有的 Trouble.nvim location list 界面。列表是创建时的快照，之后文件可能变化；需要再次核对时使用 `g`。调用栈不一定指向根因，文件身份在报错后采集，也可能不同于实际加载的代码。

前向后返回工作区按 `G` 展示本次记录中同一 Tensor 对象和版本的部分连接；默认以按调用身份聚合来源的文本图展示（排列不代表执行顺序），按 `g` 切换图与列表，在连接行按 Enter 选择端点，并可在已记录的共享别名间切换。未记录、无法读取和截断会分别标出，未看到连接不能证明连接不存在。这种运行观察借鉴模型查看器 [Netron](https://github.com/lutzroeder/netron) 的节点与连接浏览思路；工具不会安装或依赖 Netron。PyTorch 的模块遍历默认可能去重，共享对象应结合实际别名理解，参见 [PyTorch Module 文档](https://docs.pytorch.org/docs/stable/generated/torch.nn.Module.html)。

从前向报告可用 `g` 选择并打开带源码身份的已观察实现；共享模块会列出已记录路径别名（每次调用最多列出 128 个），路径相同时显示声明位置、类型及摘要以区分记录；源码内容已变化、buffer 未保存或无法核对时需要先处理。`v` 在原生列表中浏览报告里的模块，可用 `/` 搜索、`Enter` 打开详情；详情默认展示有界摘要，按 `J` 才展开完整对象。有可编辑构造参数时，可在模块详情按 `c` 选择参数及新值，或按 `w` 选择其他 Layer 修改。需要多个 Layer 同时变化时，`W` 可交互式编排或在内存中的 JSON buffer 编写批量计划，`:write` 请求预览而不保存计划文件。JSON 草稿与创建时的项目上下文绑定；上下文变化后须确认当前项目和模型并再次 `:write` 才会预览，工作区关闭后可重新打开原项目，在草稿中写入并确认连接新工作区，再次 `:write` 才会预览；草稿仍只在 Neovim 会话内保留。交互式草稿在工作区会话内保留，按 `W` 可查看或继续；项目变化时须切回原项目，预览、已应用及保存结果未知的状态会分别提示。草稿不持久化到磁盘，异常退出无法恢复。支持先修改参数再进行结构增删改的组合；目标重叠、同一源码行补丁冲突及歧义顺序会被拒绝。添加或替换层时可输入已支持的内置类型、所选 Python 环境中的 `module:factory`（例如 `torch.nn:Conv1d`），或 `component:ID@VERSION`；直接工厂由所选运行时导入，不自动安装或锁定依赖。结构操作的支持范围包括原生 `Sequential`、`ModuleList` 和 `ModuleDict`，不支持的动态代码可直接在原生 buffer 编辑。

### 使用变体试验 Layer 修改

添加层只表示将它注册到模型中，不一定会修改 `forward` 中的连接；即使候选前向成功，也不能据此认定新层执行过。请检查模型源码和对应输入下的执行记录，必要时手动修改连接并重新观察。

变体保存的是一份独立的模型修改配方，不直接改写原模型源码。可以先在模型模块详情按 `V`，输入新变体名称，再选择添加、替换、修改参数或移除层。添加或替换时可以逐项填写构造参数、输入 JSON 对象或不传参数；逐项输入中途取消可选择继续或放弃。修改单个参数时，若报告包含可编辑字段，选择字段并修改当前值；也可以手动输入字段或使用 JSON 修改多个字段。审核目标和参数后选择继续，确认执行候选前向；查看预览后可取消，或另行确认保存。保存不代表源码已修改，也不代替之后的独立前向验证。

添加或替换时输入 `?` 可以查询所选环境中 PyTorch 的 Layer 类型；查询会在确认后导入 PyTorch。选择类型后，界面提示签名报告中的必填命名参数并随填写更新。签名可能不可用或被截断，提示不能代替实际构造和前向验证；手动输入类型时也可以直接填写参数。

面板按 `Z` 查看已保存变体，在详情中选择一次前向、Layer 编辑、试跑、训练或监督预览。变体前向后按 `v` 浏览模块，进入详情按 `e` 可从所选路径继续预览编辑。调用记录截断时可切换到报告的模型结构来查找后段层；结构只说明注册情况，不证明该层在本次输入下执行。变体或源码改变后，先前的观察和监督绑定可能过期，需要重新运行并按界面提示重新绑定。动态层、外部代码和运行时依赖未必支持自动修改，仍可回到原生源码 buffer 手动编辑。

源码预览会展示差异及验证结果；在报告中按 `a` 后仍需确认，只有条件检查通过才提交。提交后若文件已在 buffer 中打开，先核对并处理磁盘与 buffer 的差异，再用 `V` 执行独立前向。候选中临时复制的参数或缓冲区不代表已迁移训练检查点；保存源码后，权重如何加载以及是否兼容取决于用户代码和检查点。候选通过和提交成功不等于独立重验通过，未固定的外部依赖、权重和数据也不能视为已验证。

成功前向后，`G` 可查看后端记录的 Tensor 连接证据，并选择来源或目标模块继续检查、预览修改或定位源码。连接仅表示同一 Tensor 对象及版本，显示的是首个路径别名，可能缺失或有多个候选来源；它不是完整图或因果证明。

用不同代表输入分别前向后，`O` 可比较近期观察的调用和输出元数据，从比较页按 `d` 选择路径继续检查或定位。记录缺失、路径未执行、调用截断、权重与随机状态未知，都不能解释为完整模型覆盖或两次运行可比。

训练使用源码快照时，若来源检查观察到项目实时 Python 模块混入，运行会报出冲突或标记失败。每次实际写入检查点前会检查当前已加载模块，发现冲突时不会写该检查点。检测不覆盖所有动态加载方式；冲突可能在部分代码或步骤已经执行后才发现，不能将失败当作没有副作用，也不会回滚已有检查点。

动态分支在训练中首次导入的项目模块，若与源码快照匹配，会作为新观察记录，而不是仅因出现得较晚就判定源码变化。新检查点保存完整源码快照摘要并在续训时比较；旧检查点可能没有该证据。快照不覆盖数据和外部依赖。

## 监督、试跑与运行

完成试跑后，结果页可以打开运行记录或准备正式训练。选择启用监督时，界面先展示规则清单，确认后再准备运行。

一次新前向完成后，可在结果页选择「标记端口并添加监督」。标记保存后从结果页为该端口添加规则，规则保存后可直接预览监督，并从预览结果进入训练试跑。规则添加仍会核对当前标记及源码身份，预览使用当前选定的输入。

成功前向后可按 `t` 为具备可核对实现身份的已观察端口手动填写语义角色和含义；端口列表可用 `/` 搜索、`Enter` 选择、`q` 返回；窄窗口可按 `w` 切换长行换行，也可使用 Neovim 的 `zl` / `zh` 横向查看；也可按 `v` 选择观察到的模块，在模块详情中按 `t` 只查看该对象的输出端口。标记会重新运行前向并要求确认；同一端口的多次调用不会重复列出，不同实现来源由后端拒绝歧义绑定。工作区要求兼容的 CLI 和 worker 在保存标记或重新绑定时核对所选实现的源码文件、摘要及类型；来源不一致则不写入。该检查不保证输入值、权重或执行中的动态代码完全相同。再按 `d` 添加规则。范围上下界及惩罚权重需为有限数，自定义规则参数会在确认时展示并写入记录，请勿填写密钥；保存自定义规则会导入用户代码。规则可观察违反情况、在支持的监督训练中阻止违规步骤，或把可微惩罚加入损失；效果取决于所选规则和训练方式。按 `u` 用代表输入预览，预览不更新参数，也不将惩罚应用到训练损失。

例如，想检查某个特征是否出现 NaN 或无穷值：先用代表输入前向，在观察到的模块输出上按 `t`，填写工程师自己定义的角色和含义；再按 `d` 选择该标记，添加 `finite` 规则并选择观察模式。用 `u` 预览后查看实际观察次数、检查数量和违反情况；未观察到的端口不是通过。如果希望支持的训练在违规时中止，再显式选择阻止模式并在试跑或训练准备时启用监督。结果只覆盖实际执行的输入和分支，不能保证整个数据集或所有训练代码。

要监督已保存的变体，在 `Z` 中选变体并运行一次前向，按 `v` 打开实际观察过的模块，再在详情按 `t` 标记端口；按 `d` 给标记添加规则，随后回 `Z` 的变体详情选择监督预览。变体修改后旧绑定可能过期：重新前向，并从标记列表选择重新绑定，保留或调整已有规则后再次预览。变体结果与源码模型的观察分开，不应把一个上下文的预览当成另一个通过。

手动标记和重新绑定时，可选择根模型 `model` 的输入或输出，也可从已记录的共享模块别名及其端口中选择；根模型需要 CLI 和 worker 支持对应能力。候选过多会提示截断，已选模块详情中仍可针对该路径标记。按 `D` 选择已保存规则，可在独立详情中查看其角色、端口、模式和参数；按 `d` 发起移除并确认，后端会核对保存的规则内容是否仍与所选内容一致。详情为有界展示，完整字段可在规则报告中查看。

观察到的列表或元组端口可使用 `outputs[0]`，嵌套字典可使用 `outputs.预测`；包含点号、方括号或控制字符的字符串键使用 JSON 引号形式，例如 `outputs["a.b"]`。为避免字符串化键产生歧义，当已记录的字典项中含非普通字符串键时，不提供该字典的下级端口候选；截断后未记录键的类型未知，不推断整个字典的键类型。过长和未记录的路径也会省略。批次对齐目标可使用同样的引号形式。这些路径和监督行为仍需人工走查。

旧记录中的点分路径可能与包含点号的键有歧义；请重新观察并核对端口，再手动创建或重新绑定标记，工具不会自动改写旧标记。 新版 CLI 在标记、规则预览、规则添加和启用监督训练时要求 worker 支持新版端口解析；不兼容时需要更新 worker，不能将旧版无法解析当作规则通过。

语义标记也绑定创建时选择的运行目录和项目模块搜索目录。更改这些路径后，使用当前配置重新前向并手动重新绑定；监督训练不会把旧路径下的标记当成当前绑定。项目代码仍可能在运行中自行更改目录，路径绑定不能证明完整运行环境相同。

标记的实现身份由源码文件、文件摘要和类型组成；报告中的声明行号只是导航提示，不参与身份判断。监督预览和训练均会核对当前模块的实现身份；训练使用源码快照时会核对快照中的对应实现。

监督预览以 `eval` 和无梯度模式执行一次前向；训练模式下的 dropout、归一化或用户分支可能产生不同结果。`require` 阻止工具管理或遵循监督上下文协议的更新，不能阻止用户代码自行执行其他更新，也不会回滚已有副作用。

监督结果显示已检查与违反数量；调用被截断或部分结果无法测量时，无违规的结果显示为部分证据，而不是完整通过。惩罚值只是本次调用的预览，不是训练损失。

同一模块多次调用时，只对成功返回的调用检查所选端口；若用户代码捕获了前向异常，未成功返回的调用计入不完整覆盖，强制和惩罚规则在工具管理的更新边界前失败。某次调用缺少端口或无法解析，会记录为无法测量；`require` 和 `penalty` 规则在工具管理的更新边界前失败，`observe` 在本次运行报告中显示未测调用数和涉及步数，旧报告没有该计数时显示未知；续训报告不因此成为完整历史覆盖。真实存在且值为 `None` 的端口与缺失端口分开处理，自定义规则可以自行判断该值。

为有限值、范围或自定义校验规则添加可选样本轴时，按输出张量的实际形状填写；逐样本定位还需要用户提供稳定样本 ID，自定义校验另需返回同形违规掩码。工具不能证明所声明 ID 的真实性。批次维度对齐规则的轴用于比较尺寸，不代表标签语义已验证。

worker 不再强制设置 PyTorch CPU 线程数。需要调整时，可在启动 Neovim 前配置所选 Python 环境，或在用户入口代码中设置；不同机器与环境可能得到不同的线程数和性能。

无变体的结构检查、Layer 查询、前向、梯度验证和监督观察保留模型工厂创建的设备；输入工厂须提供兼容的输入。变体和编辑、训练等操作仍可能先把模型迁移至 CPU，设备处理尚未统一，相关路径尚待人工验证。

上述无变体观察未指定种子时保留运行时随机状态，前向不复用缓存；显式种子、变体、编辑与训练仍按各自已有契约处理。其他随机库或用户代码仍可能改变结果，尚不能据此保证复现。

工作区 `P` 可为本会话的模型前向选择无符号 64 位种子，留空则交给 CLI/运行时策略；选定的覆盖会显示在工作区首页，确认运行前也会显示。该设置用于模型 Probe（包括局部重放、输入捕获和独立重验）、标记、重新绑定及监督预览，不自动应用到 Layer 编辑、数据预览或训练；变体的初始化种子可能不同。标记记录当次报告的种子，作为观察信息而非完整复现保证。切换种子会使当前观察过期。该入口尚待人工验证。

`P` 也可选填前向模型设备（例如 `cpu`、`cuda:0` 或所选 PyTorch 支持的设备）；留空沿用工厂位置。工具会尝试迁移模型，但不会迁移输入；设备可用性在实际运行时解析，自定义状态和副作用不保证受控。该选择用于模型 Probe、标记、重新绑定及监督预览；编辑和训练仍采用各自上下文。标记记录所选设备的解析结果，但绑定本身不保证训练使用同一设备。变体重建仍可能先经过 CPU。兼容 CLI/worker 与具体设备路径尚待人工验证。

试跑和训练可以手动输入所选 PyTorch 能解析的其他设备标识，包括已安装扩展提供的后端；实际可用性与模型迁移由运行时检查，`meta` 不用于真实训练。设备查询使用可用的 PyTorch 通用 accelerator 接口补充当前加速器，旧版本缺少该接口或查询失败时标为部分结果；它不是所有已安装后端的完整清单。`auto` 先选择可见 CUDA/ROCm，再查询可用的通用加速器，均不可用时选择 CPU；查询失败时提示错误，可改为显式选择。其他后端的内存计数可能未知。设备标识可被解析不代表该设备或训练操作已经验证。

试跑或训练中选择启用监督时，先查看规则列表、模式以及存在的范围、权重、目标和自定义函数，再确认；自定义函数参数默认只显示数量，完整字段可在报告中按 `J` 查看。列表本身不能证明规则绑定仍有效或规则会通过。启用与否由本次训练选择决定，规则不会因预览而自动启用。

添加自定义校验或惩罚函数时，工具会在所选 Python、工作目录和项目模块搜索目录下导入用户代码，并记录该函数所在源码的身份；添加前需要确认执行。使用时会先核对固定源码和目标导入位置，快照训练要求源码来自快照。查找子模块可能执行父包初始化，自定义加载器及并发变化也不能完全约束，导入过程仍可能产生副作用。

按 `y` 准备单步试跑，按 `T` 准备后台训练；可选择不启用监督，或先查看规则后启用。采用用户自己的训练代码时，以界面显示的支持条件和 context 协议为准。`R` 查看运行、日志、比较、停止、续训、评估和导出；进度查看页可暂停刷新，关闭页面不会停止训练。启动回执未知时先用 `H` 查询，不要直接重复启动。

按 `N` 可选择创建无框架训练循环草稿，在原生 buffer 中实现循环并保存；可将其作为会话循环入口。草稿使用仅 `context` 的签名，试跑或训练时需要选择该签名；旧 CLI 不声明该能力时会说明只能使用旧签名并要求用户明确选择，更新 CLI 或修改代码后才能继续。`y` 的无框架绑定用户循环试跑不要求先接入 PyTorch 模型：选择循环入口、签名、JSON 参数和步数，审核执行与运行记录的影响后启动。`F` 中选择的循环入口会作为表单候选，仍需用户审核；静态发现不验证它能否导入或运行。根据所选 CLI 能力，可使用 `loop(context, **params)` 或 `loop(None, context, **params)`，每步以 `context.report_step({"metric": number})` 报告有限标量指标，并在返回 `false` 时停止。运行记录与界面显示的是用户声明，不验证实际参数更新；试跑状态不保存。

`T` 可准备无框架正式运行；Linux 上支持的 CLI 可将其放到后台，其他情况下以前台运行。循环可通过 `context.report_step(metrics, state=state)` 明确报告 JSON 状态供保存，并在恢复时读取 `context.resume_state`；省略状态或传入 `state=None` 不会创建检查点；需要表示空值时可放入 JSON 对象，例如 `state={"value": None}`。没有报告非 None 状态就没有可供工具恢复的检查点。状态可能写入磁盘，不应包含密钥。通过 `R` 选择运行和已有检查点进行恢复，恢复使用原循环的签名与参数；源码、解释器及环境检查不覆盖外部数据或所有副作用。启动回执未知时先用 `H` 查询。试跑、正式运行和恢复的新路径均尚待人工走查。

循环可以自行提前返回。结果展示用户报告的步数与请求目标，并在新 worker 提供结束原因时说明是否在达到目标前返回；正常返回本身不证明实际训练更新或目标已完成。旧 worker 未提供原因时显示未知。

设备清单是所选 Python 环境的一次观察，硬件可见性可能随后变化；CPU 或手动输入的设备也需在运行时检查。续训继承记录的设备选择，工作区会要求当前 CLI 支持记录中的自定义设备；最终支持范围由实际后端决定，不能理解为任意加速器均已验证。

运行报告尽可能展示可用的内存计数，缺失项显示未知。通用加速器使用当前 PyTorch 的公开内存接口；若提供峰值，该值从进程启动计起，未针对本次运行重置。计数是时点观察，不保证后续运行不会耗尽内存。

受管步骤默认使用 AdamW，也可选择自己的 `module:callable` 优化器工厂；工厂接收模型和所填参数，须返回 `torch.optim.Optimizer`。它可选择可训练参数的子集，报告会说明覆盖数量；优化器的 `step()` 必须适用于当前受管步骤，工具不保证任意优化器都兼容。续训显示并继承记录的工厂，要求当前 CLI 支持该能力，且工厂、参数、类型和参数组身份一致，并核对已观察源码及环境；外部依赖文件和执行副作用并未全部固定。手动步骤可在用户代码中通过 `context.optimizer(name, parameters, factory=..., factory_params=...)` 登记自定义工厂；参数会保存到检查点，勿包含密钥。完整循环可自行管理优化器；若同时启用监督，还需支持 step 前后钩子并遵守监督 context 协议。自定义工厂及恢复路径尚待人工走查。

受管步骤可直接选择后端默认 AdamW，也可分别填写参数或选择自己的工厂。手动步骤中的默认学习率和权重衰减仅在用户代码登记 AdamW 时未提供对应值的情况下使用；代码中显式提供的值或自定义工厂不受这些默认值强制覆盖。实际使用的优化器组与更新次数以运行报告为准。

选择 PyTorch 完整循环时，可决定让循环接收当前会话或项目模型，或选择无模型并让循环自行管理；无模型时循环的 `model` 参数为 `None`，不会传入项目模型参数或组件注入。该选择需要 CLI 声明相应能力；重复运行和恢复沿用已记录的选择。循环仍由所选 PyTorch 运行时执行；无需框架绑定的用户循环可使用独立的无框架入口。

持续进度页按 `d` 可打开该运行的详情；显示的是读取时的快照，训练仍在进行时需要刷新才能看到后续状态。详情读取失败或状态未知时，先核查运行记录再决定是否重试或恢复。

运行列表及其操作菜单绑定打开时的项目上下文；菜单打开期间切换项目或运行上下文后，请重新打开列表。若停止请求发出后上下文才变化，应回到原项目核查该运行，不要假定请求没有生效。

运行列表可按 ID、名称或状态筛选当前已读取的记录；筛选不重新查询后端，状态可能已经变化。重新打开运行列表可获取新的快照。

续训准备同样绑定原项目及其上下文；查看检查点或输入额外步数期间上下文发生变化时，需要重新准备。续训请求的待确认标记保存在原项目中，回执不明确时应回原项目核查。

新训练的待确认标记也绑定原项目；使用 `H` 核查或移除标记时，如果项目上下文或所查看报告发生变化，需要重新核查。移除标记或准入锁前仍需自行检查原项目中的启动器和运行状态。

选择启用监督时，先在可滚动报告中查看规则，按 `J` 可展开完整字段，按 `a` 后才进入是否继续和实际运行的确认。运行请求固定所查看的规则修订，规则在此期间变化时后端应拒绝旧请求。手动步骤和完整循环还需用户代码接入相应的监督 context 协议。

准备试跑或训练时，如果项目或运行上下文变化，需要重新准备；异步读取的旧规则不会作为新上下文的规则继续使用。

运行记录菜单中的“本次会话使用记录的运行环境”可查看并选择记录的 Python、工作目录和模块目录，以便处理续训或评估时的上下文冲突；记录缺失或目录已变化时需要手动处理。选择只改变当前会话，不验证 Python 包、数据或硬件与历史状态相同。

不显式选择会话 Python 时，续训和评估优先使用运行记录中的解释器，并在确认前展示；续训不接受与历史记录冲突的显式解释器，评估可以明确选择其他解释器。旧记录没有解释器时才使用当前项目或默认选择。即便解释器路径相同，安装包和数据也可能已经变化。

评估报告会对照检查点记录的训练源码快照与评估时的项目源码快照，显示相同、不同或未知。不同可能只是新增了评估代码，不能据此判断指标受到影响；旧检查点可能没有完整快照摘要，该对照也不覆盖数据和依赖。

评估时可填写评估器和数据工厂参数、样本目标、预测预览数量与数据身份声明。报告显示评估器提供的指标、样本数和覆盖信息；这些声明不能证明实际数据集内容。预测可能含敏感数据：报告摘要不展示预测样本，按 `P` 才选择查看；完整结构化报告 `J` 及保存的运行记录可能包含这些数据。

## 常见中断

- 未保存或磁盘不一致：先检查涉及的 buffer，保存或自行解决差异，再重新运行。工作区不会静默保存源码。
- 当前 CLI 缺少能力：查看 `I` 和报告；仍可在源码中手工修改，必要时切换到兼容的 CLI。
- 前向失败或绑定过期：查看报告与原始证据，修改后重新前向；监督标记可重新绑定，历史观察不是当前状态。
- 回执丢失、远程断线或结果未知：先检查文件与运行记录，再决定是否重试；SSH 场景应在远端同一主机运行 Neovim、CLI 和模型，跨主机路径映射尚未实现。

此指南及 40/80 列布局、不同 Neovim/LazyVim 配置、真实复杂模型与训练流程，均需在全部实现完成后实际操作并记录结果。

运行记录对比可显示用户训练循环报告的平均指标和评估器报告的指标；两者分开展示并保留用户原始指标名。对比只描述记录，不证明数据一致或指标变化的原因。该路径待实际走查。

同一工作区会话中，试跑或 PyTorch 训练时明确输入的训练步骤/循环入口会作为后续输入默认值；仅当项目、当前模型及训练模式一致时复用，可直接修改。参数、设备、监督和执行仍需重新选择或确认；关闭工作区后不会持久保存这个入口。本地人工走查已覆盖从受管试跑入口切换到同一模型的受管训练入口；跨项目、模型和模式的行为仍待走查。

当结果返回时焦点仍在本工作区的报告中，新报告会替换当前报告，关闭一次即可返回；若用户已切换到源码或其他窗口，则另开报告而不覆盖当前 buffer。旧报告是否仍可通过运行记录重新查看取决于该操作是否有持久记录；本地已复查从续训准备到启动回执后按一次 q 返回面板；用户切换窗口的分支仍待复查。

画布的“更多”菜单提供语言切换，也可按 `F2`；支持跟随系统、英语、简体中文和繁体中文。语言偏好保存失败时只影响当前会话并显示提示。选择的节点使用 `>` 标记，端口用 `i` / `o` 标记，键盘可用 Tab、方向键、Enter 和 PgUp/PgDn 操作，不依赖颜色或鼠标。独立启动器可设置 `MODEL_MAVEN_REDUCE_MOTION=1` 减少欢迎动画，或设置 `NO_COLOR` 关闭启动器颜色；Neovim 工作区沿用用户现有主题，不更改全局主题设置。

编辑算子参数的文本、数字或 JSON 时，会打开仅在本次工作区会话中保留的输入草稿。输入完成后按 `Ctrl-S`（普通模式也可按 Enter）提交；按 `Ctrl-Q` 或普通模式 `q` 暂藏，重新打开同一参数可继续输入；`Ctrl-X` 丢弃。图在此期间发生变化时，旧输入不能直接应用，但仍可打开复制或丢弃。输入草稿独立于已保存的图，不会在关闭会话或崩溃后保证恢复；请勿在参数中填写密钥。
